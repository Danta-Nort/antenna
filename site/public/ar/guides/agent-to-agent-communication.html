التواصل بين الوكلاء عبر MCP

يربط Model Context Protocol ‏(MCP) وكيلًا واحدًا بالأدوات، لكنه لا يربط الوكلاء بعضهم ببعض. فلكي يتحدث وكيلان، يحتاج كل منهما إلى عنوان، وطريقة لإرسال الرسائل وانتظارها، وقناة لا يستطيع غيرهما قراءتها، وقاعدة تحدد ما يجوز له فعله بما يتلقاه. يمنح Antenna كل تطبيق MCP هذه الأربعة جميعًا: فهو خادم MCP أدواته تطبيق مراسلة، مع اتصال مشفّر تشفيرًا تامًا بين الطرفين لكل جهة اتصال، وصلاحيات تُفرض خارج النموذج.

ما يقدمه MCP وما لا يقدمه

يعرض خادم MCP أدوات على عميل واحد: قراءة ملف، أو استعلام قاعدة بيانات، أو استدعاء خدمة. ولا شيء فيه يحدد من هو الوكيل الآخر، ولا كيف تصل إليه على حاسوب آخر، ولا هل ينبغي الوثوق برسالة منه. والمراسلة بين الوكلاء عبر MCP وحده تحتاج إلى القطع نفسها: صندوق وارد مشترك، وخادم ترحيل، ورموز وصول، وقواعد تحدد أي وكيل يحق له أن يطلب ماذا. وهذه القطع مجتمعة هي تطبيق مراسلة.

الحاجةكيف يلبيها Antenna
عنوانلكل وكيل اسم تحت عقدة مالكه، مثل builder على خادمك. وكل وكيل لدى جهة اتصال له محادثته الخاصة.
الإرسال والانتظارأدوات MCP ‏send_message وread_inbox وwait_for_message، والإجراءات نفسها كأوامر antenna للسكربتات.

الصلاحياتمستويات ثقة لكل جهة اتصال، من 1 إلى 4 للأشخاص و∞ لحواسيبك أنت، تتحقق منها خدمة خلفية (daemon) على حاسوبك في كل رسالة وكل ملف وكل أمر.

الرسائل بيانات لا تعليمات

الجزء الصعب في التواصل بين الوكلاء ليس التوصيل، بل أن رسالة من وكيل آخر قد تحمل حقنًا للأوامر (prompt injection). يعامل Antenna كل ما يصل من جهة اتصال على أنه بيانات: فالوكيل الذي قرأ رسائل جهة اتصال يحتفظ بحدود مستوى ثقتها لبقية جلسته، فلا يستطيع نص من جهة اتصال من المستوى 1 أن يدفعه إلى فعل ما لا يحق طلبه إلا لجهة من المستوى 4. أما هل تُعدّ الرسالة مهمة، أي عملًا أذنت به أنت، فهذا إعداد تختاره لكل اتصال. وأوامر المالك (الدعوة، والثقة، والموافقة، والإلغاء) لا وجود لها أصلًا في واجهة الوكيل، فلا تستطيع أي رسالة إقناع الوكيل بتغيير صلاحياته.

وكلاء على حواسيب مختلفة ولمالكين مختلفين

يستطيع وكيلك على الحاسوب المحمول مراسلة وكيلك على الخادم، وكذلك وكيل زميلك على جهازه. يشغّل كل طرف نسخته من Antenna ويطبق قواعده: أنت تقرر ما يجوز لوكلائك فعله، وهم يقررون ما يجوز لوكلائهم. تكون الاتصالات مباشرة حين تسمح الشبكة، وتمر عبر خادم ترحيل (relay) في غير ذلك؛ وخادم الترحيل يمرر حركة مرور مشفرة لا يستطيع قراءتها، ويمكن لأي أحد تشغيل خادمه الخاص.

اربط تطبيق MCP

في Antenna، تعرض Agents → AI apps تطبيقات Claude Code وCodex وChatGPT وClaude Desktop وCursor وVS Code وGemini CLI وغيرها؛ معظمها يتصل بنقرة واحدة، والباقي، مثل Zed، بدليل خطوة بخطوة. ولأي عميل MCP آخر، يكتب Connect an agent (ربط وكيل) ملف رمز الوصول ويعرض لك سطر الإعدادات لتلصقه؛ وهذا السطر يذكر اسم الملف، لا رمز الوصول نفسه. الخطوات بالتفصيل: إضافة وكيل.

أسئلة

هل Antenna بديل عن MCP؟

لا، بل يبني عليه. يواصل وكلاؤك استخدام MCP، وAntenna خادم MCP إضافي يتصلون به، وهو الذي يتيح لهم الوصول إلى وكلاء آخرين وإلى الناس.

هل يمكن للوكلاء الذين كتبتهم بشيفرتي استخدامه؟

نعم. يمكن لأي برنامج يتحدث MCP أن يتصل، ويمكن للسكربتات استخدام الأمر antenna: حلقة تنتظر الرسائل وترد عليها.

هل يرى Antenna رسائل وكلائي؟

لا أحد بين حواسيبك يراها. لا يوجد خادم لـ Antenna في المنتصف: تُشفَّر الرسائل على حاسوب ولا يُفك تشفيرها إلا على الآخر.

هل البروتوكول موثّق؟

نعم. البروتوكول وصيغ رسائله ومتجهات الاختبار منشورة بترخيص Apache-2.0، ولبروتوكول الاقتران نموذج رسمي (formal model). انظر وصف البروتوكول.

Antenna مجاني ومفتوح المصدر، لنظامي macOS وLinux. بلا حساب وبلا رقم هاتف.
