Rode o Claude Code numa VPS o tempo todo e fale com ele pelo notebook

Instale o Claude Code e o nó do Antenna na sua VPS Linux, pareie o servidor com o seu notebook uma vez e inicie o Claude Code pelo Antenna na pasta do projeto. A partir daí, ele roda na sua própria sessão tmux depois que você sai, acorda quando chega uma mensagem para ele e responde num chat no seu notebook. Nenhuma porta de entrada para abrir, nenhuma sessão SSH para manter viva, e o Codex funciona do mesmo jeito.

O que você precisa

  • Um servidor Linux x86_64, com o Claude Code (ou o Codex) instalado e com login feito, e o tmux.
  • O Antenna no seu notebook: macOS ou Linux.

1. Instale o nó do Antenna no servidor

curl -fsSL https://antenna.contact/install.sh | sh
    sudo loginctl enable-linger $USER

O instalador lê a versão mais recente no manifesto assinado, confere o arquivo, instala o antennad e o antenna em ~/.local/bin como um serviço de usuário do systemd (sem precisar de root) e cria o seu nó com uma senha. A segunda linha mantém o serviço rodando depois que você sai. No Ubuntu ou no Fedora, você pode instalar o pacote .deb ou .rpm no lugar.

2. Pareie com o seu notebook

No notebook: New contact → Invite, dê um nome, marque This is my own computer (∞) (este é o meu próprio computador), clique em Create link e copie. No servidor:

antenna join '<link>' --trust 5 --label mac

Mantenha as aspas simples: o link contém um #. Digite no terminal do servidor o código que o notebook mostra e depois clique em The contact confirmed — codes match no notebook. O nível 5 é ∞ nos dois lados, então o servidor conta como um computador seu.

3. Inicie o Claude Code pelo Antenna

cd ~/projects/api
    antenna connect claude-code --agent api-dev --links mac --hello mac
    antenna session start api-dev --dir ~/projects/api
    antenna session attach api-dev

A linha do connect dá à sessão um agente e um token próprios e manda um oi, para que um chat chamado api-dev apareça no seu notebook. A linha do start inicia o Claude Code no servidor tmux do próprio Antenna (o seu tmux não é tocado). Conecte-se uma vez para responder às primeiras perguntas do Claude Code, por exemplo se ele confia na pasta, e depois saia com Ctrl-b d: ele continua rodando. Para o Codex, use antenna connect codex e --cli codex.

4. Fale com ele

Escreva no chat api-dev do seu notebook: “Rode os testes da migration e corrija o que falhar.” Quando o Claude Code está parado no prompt, o Antenna digita uma linha curta para que ele leia a sua mensagem; ele nunca digita o texto de um contato e nunca responde a uma pergunta no lugar dele. O cartão do servidor em My devices mostra o estado e os agentes dele, e você pode aprovar os pedidos dele pelo notebook.

Depois de um reinício

As chaves do nó ficam bloqueadas depois que o servidor reinicia: o serviço roda, mas as conexões ficam em silêncio até você fazer login e rodar antenna unlock. Assim, uma cópia do disco do servidor não entrega as suas chaves a ninguém. antenna status diz se ele está bloqueado.

Perguntas

Por que não só SSH e tmux?

Isso funciona enquanto você está no terminal. O Antenna acrescenta um chat para o qual você pode escrever do notebook a qualquer hora, acorda a sessão quando você escreve e deixa outros agentes passarem trabalho para ela, com permissões que ele mesmo confere.

O servidor precisa de IP público ou de portas abertas?

Não. Os dois lados se conectam para fora, diretamente quando a rede permite e por um relay quando não. O relay só repassa tráfego criptografado.

Posso rodar várias sessões num servidor?

Sim: um agente por pasta de projeto, cada um com nome próprio e chat próprio no seu notebook.

Existe build para ARM?

Ainda não. O nó de servidor é compilado para Linux x86_64.

O Antenna é gratuito e de código aberto, para macOS e Linux. Sem conta e sem número de telefone.
