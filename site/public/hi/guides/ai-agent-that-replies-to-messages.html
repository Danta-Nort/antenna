अपडेट किया गया 9 नवंबर 2026

ऐसा AI agent सेट करें जो आपके मैसेज का जवाब दे

Antenna में आप एक कॉन्टैक्ट और एक agent (Claude Code, Codex या आपकी अपनी कमांड) चुन सकते हैं, और उसके बाद उस कॉन्टैक्ट का हर मैसेज agent को शुरू कर देता है, जो उसे पढ़कर जवाब देता है। Antenna उसे sandbox में चलाता है, उस कॉन्टैक्ट के trust level से ज़्यादा अनुमति के बिना, और जवाब दूसरे व्यक्ति को लिखे जाते समय ही दिखने लगता है। यह आपके अपने Claude या ChatGPT साइन-इन पर चलता है, और जिस जवाब में कोई secret होने का शक हो, वह आपकी मंज़ूरी का इंतज़ार करता है।

आम इस्तेमाल

  • Server पर आपका अपना असिस्टेंट। आप लैपटॉप से अपने server को लिखते हैं, और वहाँ Claude Code जवाब देता है, आपके प्रोजेक्ट में build करता है और tests चलाता है।
  • किसी कॉन्टैक्ट के लिए फ़्रंट डेस्क। आपके प्रोजेक्ट के बारे में किसी सहकर्मी के सवालों का जवाब तुरंत मिलता है, एक ऐसे agent से जो सिर्फ़ उस बातचीत का फ़ोल्डर देखता है।
  • रिपोर्ट भेजने वाली script। किसी भी प्रोग्राम का output live stream के रूप में भेजा जा सकता है: my-program | antenna send --stream <contact>।

विंडो में सेट करें

  1. जिस कंप्यूटर पर agent चलना चाहिए, उस पर Agents → किसी कॉन्टैक्ट के लिए सेट करें… खोलें (या बातचीत में कॉन्टैक्ट कार्ड का Agent के जवाब → सेट करें…)।
  2. कॉन्टैक्ट और प्रोग्राम चुनें: Claude Code, Codex या आपकी अपनी कमांड।
  3. चाहें तो लंबे समय तक चलने वाला साइन-इन token (claude setup-token से) Value (वैकल्पिक) में पेस्ट करें। यह एक बार आपके node तक जाता है और उसके encrypted database में रखा जाता है। Mac पर यही भरोसेमंद तरीक़ा है, क्योंकि sandbox keychain नहीं खोल सकता।
  4. अपने owner password से पुष्टि करें। नियम, उसका आख़िरी run और Run log Agents में दिखते हैं।

Terminal से यह एक लाइन है: antenna wake set <contact> --cmd "claude -p --output-format stream-json"। antenna wake list नियम और हाल के runs दिखाता है; antenna wake off <contact> इसे बंद करता है।

Agent क्या कर सकता है और क्या नहीं

  • उसका prompt तय है: “आपके लिए नया मैसेज है, उसे पढ़ें और जवाब दें”। मैसेज ख़ुद कभी prompt नहीं बनता; agent उसे डेटा की तरह पढ़ता है, कॉन्टैक्ट के trust level से ज़्यादा अनुमति के बिना।
  • यह sandbox में चलता है (Linux पर bubblewrap या Landlock, macOS पर Seatbelt): यह अपना temporary फ़ोल्डर और उस बातचीत का फ़ोल्डर देखता है, और सिर्फ़ अपने model provider तक पहुँचता है। आपके प्रोजेक्ट, आपकी दूसरी फ़ाइलें और node की keys उसकी पहुँच से बाहर हैं। Sandbox न हो, तो Antenna उसे शुरू ही नहीं करता।
  • हर run साफ़ शुरू होता है, जब तक आप agent को resident न बनाएँ (नीचे देखें), ताकि पहले का कोई मैसेज बाद वाले run के लिए निर्देश न छोड़ सके।
  • सीमाएँ: हर run के लिए समय-सीमा और प्रति घंटे runs की गिनती, ताकि बहुत बातूनी कॉन्टैक्ट आपका usage न बढ़ा सके।

इसे अपने किसी प्रोजेक्ट में काम करने दें

सिर्फ़ आपके अपने कंप्यूटरों (∞) के लिए, agent आपके toolchain के साथ एक प्रोजेक्ट फ़ोल्डर में भी काम कर सकता है: --project ~/code/payments, साथ में read-only --tool-path फ़ोल्डर और वे package registries जिन तक वह --allow-host से पहुँच सकता है। किसी भी दूसरे कॉन्टैक्ट के लिए Antenna यह मना कर देता है, और आपका home फ़ोल्डर, अपना डेटा या secrets रखने वाले फ़ोल्डर, जैसे ~/.ssh, कभी नहीं खोलता।

सवाल-जवाब

क्या दूसरे व्यक्ति को जवाब टाइप होते हुए दिखता है?

हाँ, level 3 और उससे ऊपर के कॉन्टैक्ट्स के लिए: एक live bubble जो agent के लिखने के साथ बढ़ता है और आख़िर में आम मैसेज बन जाता है। Levels 1 और 2 को पूरा जवाब मिलता है।

अगर agent अपने जवाब में कोई password या key लिख दे तो?

दूसरे व्यक्ति के लिए stream रुक जाता है और मैसेज आपकी मंज़ूरी का इंतज़ार करता है। सिर्फ़ आपके अपने कंप्यूटरों तक यह आगे जाता है।

क्या इसे पिछली बातचीत याद रहती है?

Default रूप से नहीं: हर मैसेज एक नया run शुरू करता है। घंटों चलने वाले काम के लिए --resident जोड़ें: तब वही Claude Code session बातचीत के साथ बना रहता है, जो कहा और तय हुआ वह याद रखता है, और हर नया मैसेज उसकी अगली बारी बनता है। मैसेज तब भी उस तक दूसरे पक्ष के डेटा की तरह ही पहुँचते हैं।

Antenna फ़्री और ओपन सोर्स है, macOS और Linux के लिए। न अकाउंट चाहिए, न फ़ोन नंबर।
