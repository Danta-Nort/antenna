양자 내성 암호화를 쓰는 오픈소스 P2P 메신저

Antenna는 macOS와 Linux용 무료 오픈소스 P2P 메신저예요. 메시지와 파일은 QUIC으로 한 기기에서 다른 기기로 바로 가고, libsignal의 양자 내성 프로토콜로 종단 간 암호화돼요. 연결 자체에도 하이브리드 양자 내성 키 교환을 써요. 메시지를 저장하거나 중계하는 중앙 서버는 없어요. 두 기기가 서로 직접 닿지 못할 때는 복호화할 수 없는 트래픽을 릴레이가 전달해요.

실제로 P2P가 동작하는 방식

“P2P”는 간단하게 들리지만, 대부분의 컴퓨터는 들어오는 연결을 막는 공유기와 방화벽 뒤에 있어요. Antenna는 QUIC 라이브러리인 iroh를 써서 그 사이로 직접 경로를 찾고(홀 펀칭), 경로가 없으면 릴레이로 대신해요. 연결은 보통 릴레이로 시작했다가 직접 경로를 찾으면 그쪽으로 옮겨 가요. 어느 쪽이든 릴레이에는 암호화된 패킷만 보이고, 누구나 기본 릴레이 대신 자기 릴레이를 운영할 수 있어요.

같은 네트워크에 있다면, 충분히 신뢰하는 연락처와는 인터넷이 전혀 없어도 로컬 네트워크로 연결할 수 있어요.

두 겹의 암호화

계층사용하는 기술보호하는 것
연결X25519MLKEM768(기존 키 교환과 양자 내성 키 교환의 하이브리드)을 쓰는 TLS 1.3릴레이를 거치는 경우를 포함해, 두 기기 사이의 연결
메시지libsignal: 대화를 시작할 때 PQXDH, 이후에는 SPQR 양자 내성 래칫모든 메시지와 파일을 종단 간, 전방 비밀성(forward secrecy)과 함께

“양자 내성”이란, 누군가 오늘 트래픽을 기록해 두었다가 나중에 양자 컴퓨터로 복호화하려 해도 키 교환이 안전하게 유지된다는 뜻이에요. Antenna는 암호 기술을 직접 만들지 않아요. 두 계층 모두 감사를 거쳤거나 형식 검증된 라이브러리를 쓰고, 페어링 프로토콜에는 ProVerif로 검증한 형식 모델이 있어요.

P2P 설계가 바꾸는 것

  • 탈취당할 계정이 없어요. 사용자 목록이나 연락처, 메시지를 가진 서버가 없어요.
  • 전화번호가 없어요. 일회용 링크와 음성으로 비교하는 코드로 사람을 추가해요. 전화번호 없는 메신저를 참고하세요.
  • 내 IP 주소는 내 조건대로. 직접 연결하면 상대에게 내 주소가 보여요. 신뢰 레벨 1과 2의 연락처는 항상 릴레이를 거치기 때문에 내 주소를 절대 볼 수 없어요.
  • 두 기기가 동시에 온라인이어야 해요. 그전까지 메시지는 보낸 쪽의 큐에서 기다렸다가 알아서 전송돼요. 계속 켜 둔 서버가 있으면 에이전트에 언제든 닿을 수 있어요.

오픈소스이고, 직접 확인할 수 있어요

애플리케이션은 AGPL-3.0, 프로토콜과 형식, 테스트 벡터는 Apache-2.0이라서 다른 사람도 호환되는 클라이언트를 만들 수 있어요. 릴리스는 서명되어 있고, 소스 코드, 사양서, 모든 설계 결정이 GitHub에 있어요. 메시지는 서명되고 해시로 연결되며, 양쪽이 사본을 비교해서 메시지가 바뀌거나 되돌려지면 어디서 일어났는지 드러나요.

자주 묻는 질문

P2P 메신저는 더 느린가요?

보통은 아니에요. 직접 경로는 데이터 센터를 거쳐 가는 길을 건너뛰고, 릴레이를 거치면 메시지가 한 단계를 더 지날 뿐이에요.

릴레이를 직접 운영할 수 있나요?

네. 릴레이는 오픈소스이고 암호화된 트래픽을 전달하기만 해요. 노드가 기본 릴레이 대신 내 릴레이를 쓰도록 지정하면 돼요.

그룹 대화도 되나요?

아직은 안 돼요. Antenna 0.1은 일대일 대화만 지원해요. 사람끼리, 사람과 에이전트, 에이전트끼리요.

어떤 플랫폼을 지원하나요?

Apple Silicon의 macOS(서명 및 공증 완료)와 x86_64 Linux예요. 데스크톱 앱과 서버 노드가 있어요.

Antenna는 무료 오픈소스예요. macOS와 Linux에서 쓸 수 있고, 계정도 전화번호도 필요 없어요.
