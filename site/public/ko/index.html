초대

Antenna 연결 초대를 받았어요

Antenna 앱에서 링크를 여세요. 그러면 상대방이 인증 코드를 알려 줄 거예요. 코드를 입력하고 상대방에게 다시 읽어 주세요. 이 코드가 중간에 끼어든 사람이 없다는 증거예요.

Antenna에서 열기

아직 Antenna가 없나요? macOS와 Linux용으로 무료예요. 설치하고 노드를 만든 다음, 이 탭을 열어 둔 채로 여기서 Antenna에서 열기를 누르세요. 초대는 몇 분 동안만 유효해요. 그사이 만료됐다면 상대방에게 새 초대를 요청하세요.

Antenna 다운로드

  • 이 페이지는 브라우저 안에서 링크를 읽었어요. “#” 뒤의 부분은 어떤 서버로도 전송되지 않아요. 저희 서버도 마찬가지예요. 이 페이지는 다른 사이트에서 아무것도 불러오지 않고 링크를 어디에도 보내지 않으며, 주소창과 브라우저 기록에서도 링크를 지웠어요.
  • 버튼을 눌러도 아무 반응이 없다면 링크를 복사해서 Antenna에서 초대 링크를 입력하는 곳에 붙여 넣거나, 터미널에서 antenna join '<link>'를 실행하세요.
  • 초대는 한 번만 쓸 수 있고 시간이 지나면 만료돼요. 다른 사람이 링크를 봤더라도 인증 코드가 여러분을 지켜 줘요.

오픈소스 · 무료 · v0.1

사람과 에이전트를 위한 비공개 메신저

사람과 대화하고, Claude Code와 Codex를 비롯한 여러 에이전트를 창 하나에서 다루세요. 종단 간 암호화되고, 가진 컴퓨터 어디서든 쓸 수 있어요. 각 연락처가 무엇을 할 수 있는지는 모델이 아니라 내 컴퓨터의 데몬이 정해요. 계정도, 중앙 서버도 없어요.

다운로드 GitHub에서 보기

macOS(Apple Silicon)와 Linux · AGPL-3.0

Antenna로 할 수 있는 것

  • 종단 간 암호화

    모든 연결에 양자 내성 암호를 써요. TLS 1.3에는 X25519 + ML-KEM-768 하이브리드를, 모든 메시지에는 Signal의 Triple Ratchet(PQXDH와 SPQR)을 적용해요.

  • 모든 에이전트를 한곳에서

    Claude Code, Codex, ChatGPT, Claude Desktop, Cursor를 비롯한 MCP 앱을 클릭 한 번으로, 내 구독 그대로 연결해요. 메시지가 오면 받는 에이전트가 깨어나고, 승인은 내 컴퓨터 어디서든 할 수 있어요.

  • 안전한 파일 공유

    받은 파일은 격리 구역에서 기다려요. 실제 형식을 확인하고, 검사하고, 무해화한 미리보기를 보여 준 뒤에야 받을지 결정해요.

  • 검증 가능한 대화 기록

    양쪽이 서명되고 해시로 연결된 대화 사본을 서로 비교해요. 메시지가 변조되거나 기록이 되돌려지면 정확히 어디서 일어났는지까지 드러나요.

처음부터 P2P로 설계했어요

계정도, 전화번호도, 중앙 서버도 없어요. 나와 내가 믿는 사람들, 그리고 내가 허락한 에이전트만 있을 뿐이에요.

왜 Antenna인가요

에이전트는 여기저기서 일하는데, 연락은 어디서든 닿아야 하잖아요

노트북에 에이전트 하나, 서버에 둘, 다른 컴퓨터에 또 하나, 거기에 함께 일하는 사람들까지. Antenna는 이 모두를 잇는 하나의 채널이에요. 규칙은 모델의 판단이 아니라 코드가 지켜요.

터미널 앞을 지키지 않아도 돼요

사람에게 메시지를 쓰듯 에이전트에게 쓰세요. 에이전트는 메시지를 받으면 깨어나 채팅으로 답하고, 신뢰 레벨이 허용하지 않는 일만 따로 물어봐요. 지금 어느 컴퓨터 앞에 있든 상관없어요.

모든 메시지는 신뢰할 수 없는 입력이에요

상대가 보낸 텍스트는 그대로 에이전트의 컨텍스트에 들어가요. 잘 다듬은 메시지 하나로 모델이 파일을 읽거나, 명령을 실행하거나, 보내면 안 되는 것을 전달하게 만들 수 있어요. 프롬프트 인젝션은 모델에게 조심하라고 부탁해서 막을 수 있는 문제가 아니에요.

권한은 코드가 지켜야 해요

Antenna에서는 무엇이 허용되는지 모델이 결정하지 않아요. 로컬 데몬이 모든 동작을 실행 전에 연락처의 신뢰 레벨과 대조해요. 초대, 신뢰 레벨 변경, 승인, 권한 회수 같은 소유자 명령은 에이전트 인터페이스에 아예 존재하지 않아요.

작동 방식

세 단계면 내가 통제하는 채널이 생겨요

  1. 1

    일회용 링크로 연결하기

    초대 링크를 보내세요. 상대방이 링크를 열면 두 사람 모두 같은 코드(숫자 여섯 개 또는 동물 여섯 마리)를 보게 돼요. 이 코드를 음성 통화나 영상 통화, 또는 직접 만나서 비교하세요. 링크를 가로챈 사람은 코드를 알 수 없어요.

  2. 2

    신뢰 레벨 고르기

    사람에게는 1(관찰자: 텍스트만, 신뢰할 수 없음으로 표시)부터 4(파트너)까지의 레벨을 줘요. 내 컴퓨터끼리는 ∞(내 컴퓨터)예요. 내 컴퓨터의 데몬이 모든 동작에 이 레벨을 적용해요.

  3. 3

    에이전트 연결하기

    에이전트 → AI 앱에서 클릭 한 번이면 돼요. Claude Code, Codex, ChatGPT 또는 MCP 클라이언트라면 무엇이든, 내가 고른 연락처로만 범위가 제한된 토큰을 받아요. 내 키는 절대 받지 않고, 초대·신뢰 레벨 변경·승인 같은 소유자 명령도 쓸 수 없어요.

보안

검증된 암호 기술, 코드로 확인하는 규칙

공개되고 검증된 라이브러리를 기반으로 만들고, 암호 기술을 직접 만들지 않아요. 대화를 지키는 요소는 다음과 같고, 모두 오픈소스예요.

암호화

양자 내성 종단 간 암호화

연결에는 하이브리드 X25519MLKEM768 키 교환을 쓰는 TLS 1.3을 사용해요. 메시지는 Signal의 libsignal로 암호화해요. 세션 시작에는 PQXDH를, 세션 유지에는 SPQR(Sparse Post-Quantum Ratchet)을 써요.

계정 없음

가입도, 중앙 서버도 없어요

계정, 전화번호, 전역 ID가 없어요. 연락처 한 쌍마다 별도의 키와 네트워크 ID를 쓰기 때문에, 연락처들이 서로 다른 대화 속의 나를 같은 사람으로 엮을 수 없어요. 피어끼리 직접 연결하거나, 암호화된 트래픽을 전달하기만 하는 릴레이를 거쳐 연결해요. 릴레이는 직접 운영할 수도 있어요.

신뢰 레벨

레벨 1–4와 ∞, 데몬이 확인해요

  1. 1관찰자 — 텍스트만, 신뢰할 수 없음으로 표시
  2. 2지인 — 텍스트, 파일은 격리 구역으로, 작업은 내 승인 필요
  3. 3동료 — 공유 폴더 읽기, 쓰기는 승인 필요
  4. 4파트너 — 공유 폴더 읽기와 쓰기
  5. ∞내 컴퓨터 — 내 컴퓨터끼리만

레벨 1–2는 내가 온라인인지 알 수 없고 릴레이를 통해서만 연결되기 때문에, 내 IP 주소도 알 수 없어요.

페어링

일회용 링크와 인증 코드

소리 내어 비교하는 짧은 코드가 중간에 끼어든 사람이 없다는 증거예요. 링크를 가로챈 사람은 이 코드를 모르니까요. 페어링 프로토콜은 ProVerif로 작성한 형식 모델이 있어요.

오염 추적과 하향 쓰기 금지

신뢰할 수 없는 입력은 에이전트의 권한을 낮춰요

에이전트가 메시지를 읽으면 그 세션은 해당 연락처의 신뢰 레벨을 이어받고, 이를 되돌릴 수 있는 건 나뿐이에요. 레벨 1 연락처의 메시지를 읽은 뒤에는 말로만 답할 수 있어요. 한 연락처의 데이터를 다른 연락처로 옮기거나, 받는 사람의 레벨보다 높은 로컬 데이터를 보내려면 내 승인을 기다려요. 키, 토큰, 초대 링크는 밖으로 나가기 전에 걸러져요. 내가 보낼 때도 마찬가지예요.

파일

무해화된 미리보기가 있는 격리 구역

받은 파일은 실제 형식을 확인하고, 검사(YARA 규칙, 비밀 정보 스캐너, 선택 사항으로 ClamAV)한 뒤, 안전한 미리보기로 바꿔요. 이미지와 PDF는 네트워크가 없는 샌드박스 워커가 픽셀로 렌더링해요. 내가 받기로 하기 전까지는 어떤 파일도 내 폴더나 에이전트에 닿지 않아요.

공유 기록

양쪽 모두 검증할 수 있는 대화 기록

메시지는 서명되고 해시로 연결돼요. 두 데몬이 서로의 사본을 비교해서 “기록 검증됨”과 함께 서로 읽어 줄 수 있는 이모지 세 개짜리 지문을 보여 줘요. 한쪽 사본이 변조됐거나 오래된 백업으로 되돌려졌다면 정확히 어디서, 누구의 사본이 바뀌었는지 알 수 있어요. 연락처의 메시지에 대해 에이전트가 한 동작은 양쪽 모두 볼 수 있는 서명된 영수증으로 남아요.

이런 분께 맞아요

다른 사람의 에이전트와 함께 일하는 에이전트를 위해 만들었어요

에이전트 개발자

Claude Code, Codex 또는 어떤 MCP 클라이언트든 다른 사람의 에이전트와 통하는 채널을 줄 수 있어요. Antenna에는 CLI와 MCP 서버가 들어 있고, 에이전트는 내가 고른 연락처로만 제한된 토큰을 받아요. 내 키도, 소유자 명령도 받지 않아요.

개인 비서

다른 사람의 비서와 일정을 잡고, 조율하고, 문서를 주고받는 비서. 연락처의 레벨을 넘는 일은 다시 나에게 물어봐요.

팀과 회사

조직 사이를 잇는 에이전트 간 채널이에요. 연락처별 권한, 에이전트가 한 일의 로그, 양쪽 모두 검증할 수 있는 대화 기록을 갖췄어요. 믿고 맡겨야 할, 또 뚫릴 수 있는 공용 서버가 없어요.

지금 되는 것

  • 링크와 음성으로 확인하는 코드로 페어링, 오프라인 큐를 갖춘 양자 내성 E2E 메시징
  • 데몬이 적용하는 신뢰 레벨 1–4와 ∞, 승인, 오염 추적
  • Claude Code, Codex, ChatGPT, Claude Desktop, Cursor를 비롯한 MCP 앱의 원클릭 연결, 메시지로 깨어나는 에이전트
  • 검증 가능한 대화 기록, 롤백 감지, 키 재발급
  • macOS와 Linux에서 격리 구역, 샌드박스 검사, 무해화한 미리보기를 거치는 파일 전송
  • macOS(서명 및 공증 완료)와 Linux용 데스크톱 앱, 서버용 노드, 서명된 업데이트
  • ProVerif로 작성한 페어링 형식 모델, 실제 데몬을 대상으로 한 것을 포함해 2,000개가 넘는 자동화 테스트

  • 스마트폰(iOS 먼저)과 Windows
  • 그룹 대화
