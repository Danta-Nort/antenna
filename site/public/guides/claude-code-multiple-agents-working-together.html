Run multiple Claude Code agents working together on one project

In Antenna, a team is a lead agent and workers on one git project. You set a budget once (for example “up to 2 Claude Code coders”), and the lead splits the work into tasks, starts workers within that budget, reviews each result and sends it back or accepts it. Every worker codes in parallel in its own sandbox, on its own copy of the project, and the team’s work reaches your branch only when you approve it. Experimental.

The problem with several agents in one folder

Running two or three Claude Code sessions side by side is easy; keeping them from stepping on each other is not. They edit the same files, run commands in the same folder, and each one can read everything the others can. Someone has to hand out tasks, check what comes back and merge it, and that someone is usually you, switching between terminals.

How a team works

  1. You create the team in Teams → New team: the project folder, the lead (one of your agents, a local model, or you), the budget of workers, and the rules: whether workers may run commands, which Check commands a task may name (cargo test, npm test), and which package registries those checks may reach.
  2. You give the lead the goal, in its own terminal: “Split the login feature into small tasks for two coders.”
  3. The lead plans and staffs. It writes tasks, starts workers such as web.coder-1 within the budget, and assigns them.
  4. Workers code in parallel. Each gets a fresh copy of the project at the team’s branch, reads only its own task, works, and submits, or asks the lead a question when it is stuck.
  5. Antenna checks every result by running the task’s check command in a separate sandbox with no tokens and no network beyond the registries you named. A failing check goes back to the worker by itself, up to a limit, before the lead decides.
  6. The lead reviews: accept, or send back with comments. Accepted work collects on a team branch, antenna/web.
  7. You apply it. Review and apply shows what will be merged into your branch; with your password it is merged, as a fast-forward. Without it, nothing moves.

What you see

The team’s board shows every task by state, from Open and Working to In review, Blocked, Accepted and Applied, with each worker’s live output, what its result changes, the check’s output and the tokens it used. You can do anything the lead can: answer a worker’s question, request changes, cancel a task or stop a worker. When the lead runs in Antenna’s Code mode, it is woken whenever a worker submits or asks something, so the team keeps moving while you are away.

What keeps the project safe

  • Workers never see your folder, your other files or each other’s copies, and reach only their model provider.
  • The lead cannot raise its own budget, approve anything for you or see a worker’s token: Antenna, not the model, decides every call.
  • Untrusted input stays contained. A task written after reading a level-2 contact’s message runs no commands and no checks, so an instruction slipped into that message cannot reach your computer.
  • Local only, if you want. A team can be limited to models running on your own computer, with no cloud model at all.

Questions

Which agents can be workers?

Claude Code with your own login, another program that speaks Claude Code’s stream-json, or a local model for lighter roles such as triage, summaries and docs.

Can the lead be Codex or another app?

The lead can be any of your agents connected to Antenna: it gets the team tools over MCP the next time its app starts. You can also lead the team yourself from the board.

How do I limit cost?

The budget caps how many workers of each kind may exist, and the rules cap the time of a turn and of a check and the tokens a task may use.

Does it work on my Mac?

Yes, on macOS and Linux. Workers run on the computer where the team lives; workers on your other computers come later.

Antenna is free and open source, for macOS and Linux. No account, no phone number.
