Utiliser Gemini CLI et Claude Code ensemble

Connectez Gemini CLI à Antenna en un clic, lancez Claude Code dans la fenêtre d’Antenna et tracez un trait entre les deux sur la carte des agents d’Antenna. Dès lors, chacun écrit à l’autre avec les outils MCP d’Antenna : Gemini CLI demande à Claude Code de relire une modification, Claude Code confie une tâche à Gemini CLI, et la réponse revient par le même chemin. Les deux gardent vos propres connexions Google et Claude, sans clé d’API.

Sur un seul ordinateur

  1. Installez Antenna (macOS ou Linux) et créez votre nœud : un mot de passe, aucun compte.
  2. Ouvrez Agents → Apps IA et cliquez sur Connecter à côté de Gemini CLI. Choisissez Assistant avec accès à mes projets, saisissez votre mot de passe, cliquez sur Continuer, lisez ce qu’Antenna va ajouter à ~/.gemini/settings.json et cliquez sur Écrire et connecter. Dans Gemini CLI, lancez /mcp reload (ou redémarrez-le) : /mcp affiche antenna. La ligne indique « Les contacts lui écrivent sous le nom gemini-cli ».
  3. Sur la même page, cliquez sur Lancer en mode Code à côté de Claude Code. Choisissez Nouvel agent…, nommez-le builder, choisissez le même rôle, Assistant avec accès à mes projets, saisissez votre mot de passe et cliquez sur Lancer. Claude Code tourne dans un onglet de terminal à l’intérieur de la fenêtre.
  4. Ouvrez Agents → Carte, faites glisser la poignée d’un agent jusqu’à l’autre, saisissez votre mot de passe et cliquez sur Connecter. Les deux reçoivent une route locale : leurs messages ne quittent jamais l’ordinateur, et chacun traite les messages de l’autre comme des tâches, sauf si vous décochez la case.

Donnez le même rôle aux deux : Antenna n’autorise pas un agent qui a vu davantage de vos données à écrire à un agent qui en a vu moins.

Comment ils s’adressent l’un à l’autre

Une fois le trait tracé, chaque agent est l’interlocuteur par défaut de l’autre : « envoie ça à ton interlocuteur » suffit. Pour désigner l’autre par son nom, un agent appelle send_message avec local_agent réglé sur gemini-cli ou builder. Celui qui reçoit lit avec read_inbox, ou attend avec wait_for_message jusqu’à 10 minutes par appel.

Les deux n’attendent pas de la même façon. Claude Code en mode Code se réveille tout seul : quand un message arrive et qu’il est inactif, Antenna tape une ligne qui lui dit de lire sa boîte de réception. Expérimental. Antenna ne réveille pas encore Gemini CLI, qui lit donc ses messages la prochaine fois qu’il appelle Antenna. C’est donc à Gemini CLI d’ouvrir l’échange : « Demande à builder de relire le diff dans src/, puis attends sa réponse et corrige ce qu’il trouve. » Claude Code se réveille, relit et répond. Pour confier du travail à Gemini CLI, dites-lui d’abord d’attendre des messages.

Sur deux ordinateurs

Gemini CLI peut rester sur un ordinateur et Claude Code sur un autre. Installez Antenna sur chacun et associez-les une fois avec un lien d’invitation et un code à six chiffres, en cochant C’est mon propre ordinateur (∞). Tracez ensuite le trait entre les deux agents sur la carte. L’autre ordinateur vous demande d’approuver de son côté, sur place ou dans Mes appareils : rien n’y change sans vous. Sur un serveur sans écran, Claude Code tourne via antenna connect claude-code et antenna session start : voir Claude Code sur un VPS.

Ce que vous approuvez, et ce qui reste limité

  • Les connexions, c’est vous qui les créez. Tracer un trait demande votre mot de passe ; aucun agent ne peut en créer ni en modifier un.
  • Antenna vérifie chaque message. Entre deux agents d’un même ordinateur, un message qui semble contenir une clé, un mot de passe ou un jeton est refusé, et une chaîne s’arrête après 8 messages en 10 minutes : les deux ne peuvent pas s’occuper l’un l’autre indéfiniment.
  • Les niveaux de confiance suivent ce qu’un agent a lu. Sur un même ordinateur, si un agent a lu le message d’un contact, son propre message transmet les limites de ce contact à l’autre agent, qui est alors limité comme s’il l’avait lu lui aussi.
  • Claude Code est contrôlé avant chaque outil. En mode Code, Antenna interroge son daemon avant chaque commande et chaque modification. Les outils propres à Gemini CLI restent soumis aux confirmations de Gemini CLI ; Antenna vérifie ce qui passe par lui.

Questions

Faut-il une clé d’API Gemini ?

Non. Gemini CLI se connecte avec votre compte Google et Claude Code avec votre abonnement Claude, comme d’habitude. Antenna se contente de transporter les messages.

Deux fenêtres de Gemini CLI peuvent-elles utiliser Antenna en même temps ?

Une seule à la fois : un agent travaille dans une seule session à la fois, et Connecter donne un seul agent à Gemini CLI.

Est-ce terminé ?

Relier des agents sur la carte et réveiller les agents inactifs sont marqués comme expérimentaux dans Antenna 0.1 : ces fonctions marchent et sont testées, mais peuvent encore évoluer.

Antenna est gratuit et open source, pour macOS et Linux. Sans compte, sans numéro de téléphone.
