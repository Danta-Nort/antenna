让多个 Claude Code 智能体协作开发同一个项目

在 Antenna 中，一个团队由一个主导智能体和若干工作智能体组成，共同开发一个 git 项目。你只需设定一次预算（比如“最多 2 个 Claude Code 编码智能体”），主导智能体就会把工作拆成任务，在预算内启动工作智能体，审查每个结果，要么打回、要么接受。每个工作智能体都在自己的沙盒里、在自己的项目副本上并行写代码，团队的成果只有经过你批准才会进入你的分支。实验性功能。

多个智能体挤在一个文件夹里的问题

同时跑两三个 Claude Code 会话很容易，难的是不让它们互相干扰。它们会改同样的文件，在同一个文件夹里执行命令，而且每一个都能读到其他几个能读到的所有东西。总得有人分派任务、检查交回来的结果、再合并进去，而这个人通常就是你，在几个终端之间来回切换。

团队如何运作

  1. 你创建团队，在 团队 → 新建团队 中设置：项目文件夹、主导者（你的某个智能体、一个本地模型，或者你自己）、工作智能体的预算，以及规则：工作智能体能否执行命令，任务可以指定哪些 检查命令（如 cargo test、npm test），以及这些检查可以访问哪些软件包仓库。
  2. 你把目标交给主导智能体，在它自己的终端里说：“把登录功能拆成小任务，分给两个编码智能体。”
  3. 主导智能体制定计划、分配人手。它写好任务，在预算内启动 web.coder-1 这样的工作智能体，并把任务分配给它们。
  4. 工作智能体并行写代码。每个工作智能体都拿到一份基于团队分支的全新项目副本，只读自己的任务，完成后提交；卡住时可以向主导智能体提问。
  5. Antenna 检查每个结果：在一个单独的沙盒里运行任务指定的检查命令，沙盒里没有任何令牌，网络也只能访问你指定的仓库。检查失败的结果会自动退回给工作智能体，达到次数上限后再交由主导智能体决定。
  6. 主导智能体审查：接受，或者附上意见打回。接受的成果汇集到团队分支 antenna/web 上。
  7. 由你来合并。审查并应用 会显示将要合并进你分支的内容；输入密码后以 fast-forward 方式合并。没有你的密码，什么都不会动。

你能看到什么

团队看板按状态展示每个任务，从“待领取”“进行中”到“审查中”“受阻”“已接受”和“已应用”，同时能看到每个工作智能体的实时输出、它的结果改动了什么、检查的输出以及消耗的 token。主导智能体能做的事你都能做：回答工作智能体的问题、要求修改、取消任务或停止某个工作智能体。主导智能体在 Antenna 的 Code 模式下运行时，每当有工作智能体提交或提问，它都会被唤醒，所以你不在的时候团队也能继续推进。

如何保证项目安全

  • 工作智能体永远看不到你的文件夹、你的其他文件或彼此的副本，网络上也只能访问自己的模型服务商。
  • 主导智能体无法提高自己的预算、无法替你批准任何事，也看不到工作智能体的令牌：每一次调用都由 Antenna 决定，而不是模型。
  • 不可信的输入会被隔离。读过 2 级联系人的消息之后写出的任务，不会执行任何命令和检查，所以混进那条消息里的指令到不了你的电脑。
  • 可以只用本地模型。团队可以限定只使用在你自己电脑上运行的模型，完全不用云端模型。

常见问题

哪些智能体可以当工作智能体？

使用你自己登录的 Claude Code、其他支持 Claude Code stream-json 格式的程序，或者本地模型（适合分类、总结、写文档这类较轻的角色）。

主导智能体可以是 Codex 或其他应用吗？

主导者可以是你接入 Antenna 的任何一个智能体：它的应用下次启动时，就会通过 MCP 拿到团队工具。你也可以自己在看板上主导团队。

怎么控制成本？

预算限制了每种工作智能体最多能有几个，规则则限制了每一轮和每次检查的时长，以及每个任务能用的 token 数。

在我的 Mac 上能用吗？

能，macOS 和 Linux 都支持。工作智能体运行在团队所在的那台电脑上；在你其他电脑上运行工作智能体，要等以后的版本。

Antenna 免费且开源，支持 macOS 和 Linux。不需要账号，也不需要手机号。
