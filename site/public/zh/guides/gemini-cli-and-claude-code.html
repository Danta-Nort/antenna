让 Gemini CLI 和 Claude Code 协同工作

一键把 Gemini CLI 接入 Antenna，在 Antenna 的窗口里启动 Claude Code，再在 Antenna 的智能体地图上把两者连起来。从此它们就用 Antenna 的 MCP 工具互相发消息：Gemini CLI 请 Claude Code 审查一处改动，Claude Code 把任务交给 Gemini CLI，回复沿同一条路返回。两者都照常用你自己的 Google 和 Claude 账号登录，不需要 API key。

在同一台电脑上

  1. 安装 Antenna（macOS 或 Linux）并创建你的节点：设一个密码就行，不需要账号。
  2. 打开 智能体 → AI 应用，点 Gemini CLI 旁边的 接入。选择 可以访问我的项目的助理，输入密码，点 继续，看一下 Antenna 会往 ~/.gemini/settings.json 里添加什么，然后点 写入并接入。在 Gemini CLI 中运行 /mcp reload（或者重新启动它）：/mcp 会列出 antenna。应用列表里这一行会显示“联系人用 gemini-cli 这个名称给它发消息”。
  3. 在同一页面，点 Claude Code 旁边的 以 Code 模式启动。选择 新智能体…，命名为 builder，选同样的角色 可以访问我的项目的助理，输入密码后点 启动。Claude Code 会在窗口内的一个终端标签页里运行。
  4. 打开 智能体 → 地图，从一个智能体的连接点拖一条线到另一个，输入密码，点 连接。两者之间会建立一条本地路由：它们的消息永远不会离开这台电脑，而且双方都会把对方的消息当作任务来执行，除非你取消勾选。

给两者设定同样的角色：Antenna 不允许看过你更多数据的智能体给看得更少的智能体写消息。

它们如何找到对方

连好线之后，两个智能体互为默认的对接方：说一句“把这个发给你的搭档”就够了。如果要点名，智能体调用 send_message，把 local_agent 设为 gemini-cli 或 builder。接收方用 read_inbox 读取消息，或者用 wait_for_message 等待，每次调用最多等 10 分钟。

两者等消息的方式不一样。Code 模式下的 Claude Code 会自己醒来：消息到达时如果它正空闲，Antenna 会替它输入一行字，让它去读收件箱。实验性功能。Antenna 目前还不能唤醒 Gemini CLI，所以 Gemini CLI 要等到下一次调用 Antenna 时才会读到消息。因此由 Gemini CLI 发起对话最顺手：“请 builder 审查 src/ 里的 diff，然后等它回复，把它发现的问题修好。”Claude Code 醒来、审查、回复。要给 Gemini CLI 派活，先让它等待消息。

在两台电脑上

Gemini CLI 可以留在一台电脑上，Claude Code 放在另一台。两台电脑都装上 Antenna，用一个邀请链接加一个六位数验证码配对一次，并勾选 这是我自己的电脑（∞）。然后在地图上把两个智能体连起来。另一台电脑会请你批准它那一侧的变更，在那台电脑上或在 我的设备 中批准都可以，所以那边的任何改动都不会绕过你。在没有屏幕的服务器上，Claude Code 通过 antenna connect claude-code 和 antenna session start 运行：见在 VPS 上运行 Claude Code。

哪些要你批准，哪些仍有限制

  • 连接由你决定。连线需要输入你的密码；任何智能体都无法创建或修改连接。
  • Antenna 检查每一条消息。在同一台电脑的两个智能体之间，看起来含有密钥、密码或令牌的消息会被拒绝；10 分钟内连续 8 条消息后，这条消息链就会中止，两者没法永远互相占着对方。
  • 信任级别跟着智能体读过的内容走。在同一台电脑上，如果一个智能体读过某个联系人的消息，它发给另一个智能体的消息就会带上这个联系人的限制，接收方也会像自己读过那条消息一样受到限制。
  • Claude Code 每次使用工具前都要经过检查。在 Code 模式下，Antenna 会在每条命令、每次编辑之前询问自己的守护进程。Gemini CLI 自己的工具仍由 Gemini CLI 自己的确认机制管理；Antenna 检查的是经过它的内容。

常见问题

需要 Gemini API key 吗？

不需要。Gemini CLI 照常用你的 Google 账号登录，Claude Code 照常用你的 Claude 套餐。Antenna 只负责传递消息。

两个 Gemini CLI 窗口能同时使用 Antenna 吗？

一次只能一个：一个智能体同一时间只在一个会话中工作，而 接入 只给 Gemini CLI 分配一个智能体。

这个功能已经完善了吗？

在 Antenna 0.1 中，在地图上连接智能体和唤醒空闲智能体都标为实验性功能：它们能用，也经过了测试，但之后仍可能调整。
