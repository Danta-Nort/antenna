防止 AI 智能体泄露 API key 和密码

把你的 AI 智能体接入 Antenna 后，由你电脑上的 Antenna 守护进程（而不是模型）检查它们经由 Antenna 发出的一切：消息、文件及其中的文字、文件名和流式回复。任何看起来像私钥、API 令牌、密码或助记词的内容都会被扣下，直到你批准。收到的文件在检查完成前一直待在加密的隔离区里；智能体一旦读过信任度较低的联系人的消息，就会失去运行命令的权利。

扫描器能发现什么

  • 私钥：PEM 和 OpenSSH 密钥、PGP 私钥块、PuTTY 密钥文件、age 私钥。
  • API 令牌，按已知格式识别：GitHub、GitLab、AWS 访问密钥 ID、sk- 和 sk-ant- 密钥、Google API key、Stripe 密钥、JSON Web Token，以及 Antenna 自己的智能体令牌和邀请链接。
  • 带标签的值：password=、api_key:、token=、client_secret 等，后面跟着六个或更多字符；还能识别另外十几种语言里表示“密码”的词。
  • 助记词：连续十二个或更多钱包恢复词。

它看的是格式，不是含义：一串既没有已知前缀、也没有标签的随机字符会被放过。

它检查哪些地方

  • 智能体发给联系人的每条消息，也包括你自己的消息。
  • 每个文件在发出之前都会被检查，包括 PDF、文档和压缩包里的文字，以及文件名。
  • 流式回复，逐段检查：一旦出现机密信息，对方那边的流就会中断，整条消息等你处理。
  • 同一台电脑上的两个智能体之间（实验性功能），含有机密信息的消息会被直接拒绝。

发现之后会怎样

被扣下的智能体消息会在聊天里显示为 Waiting for your approval（等待你批准），并写明发现了什么，比如“looks like a secret: token”。Approve 需要你的密码，在 Mac 上也可以用 Touch ID（实验性功能），然后原样发送你看到的内容；Deny 则丢弃它。你自己被扣下的消息和被扣下的文件会提供 Approve and send，文件还会提供 Don’t send。无人处理的请求在 10 分钟后关闭，什么也不会发出去。

信任越低，权限越小

智能体一旦读过某个联系人的消息，在本次会话剩下的时间里都受这个联系人级别的限制；对于通过 Antenna 启动的 Claude Code，每条命令、每次读取和编辑都会被检查：

级别读过对方消息后的你的智能体对方的文件
1 · Observer（观察者）只能用文字回答无
2 · Acquaintance（熟人）每次读取和编辑都要等你批准；不能运行命令进入隔离区，逐个由你决定
3 · Colleague（同事）可以读取；编辑要等你批准；不能运行命令检查后等你点 Accept
4 · Partner（伙伴）可以在对方的文件夹里读取和编辑；其他编辑和所有命令都要等你批准检查后等你点 Accept

像 curl 这样的命令发送数据时不经过 Antenna，所以 Antenna 的做法是限制命令，而不是去读命令的内容。此外，智能体一旦读过你项目里的文件，它发给 ∞ 以下联系人的每条消息都要等你批准；一旦读过某一段对话，发往另一段对话的消息同样要等你批准。

收到的文件

联系人发来的文件以加密状态留在隔离区里，你的智能体根本没有路径能访问它。Antenna 按内容判断文件类型，在一个没有网络、也无法访问你文件的沙盒里扫描其中的威胁和机密信息，并重新生成一份安全的预览。程序、安装包以及装有它们的压缩包，要等你点 Keep anyway（仍然保留）并输入密码；智能体无法保留它们。如果沙盒无法启动，文件就不会被检查，任何智能体都不能接收它。

你自己的电脑（∞）

∞ · My computer 是唯一的例外，而且是有意为之，好让你能在笔记本和服务器之间传自己的 .env。发往你自己电脑的消息和文件不经询问直接发出，包括机密信息，流式回复也不会被截断；只有来自其他联系人对话的数据仍要等你批准。Antenna 仍会扫描每一条，并把发现的内容写进那台电脑的 Activity log（活动日志）。选择 ∞ 时会先显示一条警告；永远不要给别人的电脑选 ∞。

常见问题

智能体能关掉扫描器吗？

不能。扫描器由守护进程运行，智能体没有任何命令可以改动它，批准还需要你的密码或指纹。

Antenna 能阻止通过 git 或网络请求泄露吗？

不能靠扫描：它只能看到经过 Antenna 的内容。收到 1–3 级联系人的消息之后，通过 Antenna 启动的 Claude Code 完全不运行命令；在 4 级，每条命令都要等你批准。

Antenna 免费且开源，支持 macOS 和 Linux。不需要账号，也不需要手机号。
