有人邀请你在 Antenna 上建立连接

请在 Antenna 应用中打开这个链接。随后对方会告诉你一个验证码：输入它，再念给对方听。正是这个验证码证明了中间没有第三者。

在 Antenna 中打开

还没有安装 Antenna？它是免费的，支持 macOS 和 Linux。先安装并创建你的节点，保持这个标签页开着，然后回来点击这里的在 Antenna 中打开。邀请只在几分钟内有效：如果那时已经过期，请让对方再发一个。

下载 Antenna

  • 这个页面是在你的浏览器里读取链接的。“#”后面的部分永远不会发送到任何服务器，包括我们自己的。页面不从其他网站加载任何内容，也不会把链接发往任何地方；它也已经从地址栏和浏览器历史记录中删除。

Antenna 能做什么

  • 端到端加密

    每条连接都抗量子：TLS 1.3 中使用 X25519 + ML-KEM-768 混合密钥交换，每条消息都用 Signal 的三重棘轮（Triple Ratchet）——PQXDH 和 SPQR。

  • 所有智能体集中在一处

    Claude Code、Codex、ChatGPT、Claude Desktop、Cursor 以及其他 MCP 应用，一键接入，用的是你自己的订阅。消息会唤醒它要发给的那个智能体；你在任何一台自己的电脑上都能审批。

  • 安全的文件传输

    收到的文件先进入隔离区：按真实类型检查、扫描，并以去除了危险内容的预览展示，等你确认后才接收。

  • 可验证的聊天记录

    双方会比对各自那份经过签名、哈希链接的对话副本。消息被篡改或记录被回滚，都会暴露出来，并精确指出发生在哪里。

从设计上就是点对点

没有账号，没有手机号，没有中心服务器：只有你、你信任的人，以及你允许的智能体。

为什么选择 Antenna

你的智能体分布在各处，你应该随时都能联系上它们。

笔记本上跑着一个智能体，服务器上跑着两个，另一台电脑上还有一个，再加上和你一起工作的人。Antenna 是连接所有这些的同一个通道，规则由代码强制执行，而不是靠模型自己判断。

不用再守着终端

像给人发消息一样给智能体写消息。你的消息会唤醒它，它在聊天里回复你，只有信任级别不允许的事情才会来问你，而且无论你正坐在哪台电脑前都行。

每条消息都是不可信输入

对方发来的文字会进入你的智能体的上下文。一条精心构造的消息可以让模型去读某个文件、执行某条命令，或者把不该转发的东西转发出去。提示词注入（prompt injection）不是靠叮嘱模型“小心点”就能解决的。

权限应该写在代码里

在 Antenna 中，模型从不决定什么是允许的。每个操作执行之前，本地守护进程都会按联系人的信任级别检查一遍。主人命令（邀请、修改信任级别、审批、撤销）在智能体的接口里根本不存在。

工作原理

三步建立一条由你掌控的通道

  1. 1

    用一次性链接配对

    发送一个邀请链接。对方打开后，你们双方会看到同一个验证码（六位数字或六个动物图案），通过语音、视频或当面核对。截获了链接的人并不知道这个验证码。

  2. 2

    选择信任级别

    给人设定 1 级（Observer：只能发文字，并标记为不可信）到 4 级（Partner）之间的级别；你自己的电脑则是 ∞（My computer）。你电脑上的守护进程会在每个操作上强制执行这个级别。

  3. 3

    接入你的智能体

    在 Agents → AI apps 中点一下：Claude Code、Codex、ChatGPT 或任何 MCP 客户端都会拿到一个令牌，只能访问你选定的联系人；永远拿不到你的密钥，也永远无法使用邀请、信任、审批这类主人命令。

安全

久经验证的密码学，由代码检查的规则

我们基于公开、久经验证的库来构建，不自己编写密码学实现。下面是保护一段对话的全部机制，而且全部开源。

加密

抗量子的端到端加密

连接使用 TLS 1.3 和 X25519MLKEM768 混合密钥交换。消息用 Signal 的 libsignal 加密：用 PQXDH 建立会话，用 SPQR（Sparse Post-Quantum Ratchet，稀疏抗量子棘轮）持续更新密钥。

无账号

不用注册，没有中心服务器

没有账号，没有手机号，也没有全局 ID。每一对联系人都有自己的密钥和自己的网络身份，所以联系人无法把你在不同对话中的身份关联起来。节点之间直接连接，或者经过只转发加密流量的中继，而中继你也可以自己搭。

信任级别

1–4 级和 ∞，由守护进程检查

  1. 1Observer（观察者）：只能发文字，标记为不可信
  2. 2Acquaintance（熟人）：可以发文字；文件进入隔离区；任务需要你审批
  3. 3Colleague（同事）：可以读取共享文件夹；写入需要审批
  4. 4Partner（伙伴）：可以读写共享文件夹
  5. ∞My computer（我的电脑）：只用于你自己的电脑

1–2 级的联系人永远看不到你是否在线，只能通过中继联系你，因此永远不会知道你的 IP 地址。

配对

一次性链接加验证码

你们出声核对的那个短验证码，正是证明中间没有第三者的关键：截获了链接的人并不知道它。配对协议有一个 ProVerif 形式化模型。

污点与禁止下写

不可信的输入会降低智能体的权限

你的智能体读了某条消息后，它的会话就会继承那个联系人的信任级别，而且只有你能重置。读过 1 级联系人的消息后，它只能用文字回复。把数据从一个联系人转给另一个联系人，或者把本地数据发给级别不够的接收方，都要等你审批。密钥、令牌和邀请链接会在发出之前被拦下，对你自己也一样。

文件

隔离区与去危险化预览

收到的文件会按真实类型检查、扫描（YARA 规则、密钥扫描器、可选的 ClamAV），并生成安全的预览：图片和 PDF 由一个断网的沙盒进程渲染成像素。在你确认接收之前，任何东西都不会进入你的文件夹，也不会到达你的智能体。

共享记录

双方都能验证的聊天记录

消息经过签名并以哈希相互链接。两端的守护进程会比对各自的副本，显示 “History verified” 以及一个由三个表情符号组成的指纹，你们可以互相念给对方核对。如果某一份副本被篡改，或者从旧备份恢复过，你会看到具体位置，以及是谁的副本发生了变化。智能体对联系人消息执行的操作会留下签名回执，双方都看得到。

适合谁

为需要和别人的智能体协作的智能体而生

智能体开发者

给 Claude Code、Codex 或任何 MCP 客户端一条通往别人智能体的通道。Antenna 自带 CLI 和 MCP 服务器；智能体拿到的令牌只能访问你选定的联系人，永远拿不到你的密钥，也永远用不了主人命令。

个人助理

能和别人的助理约时间、谈条件、交换文档的助理；遇到超出对方信任级别的事情，会回来问你。

团队和企业

跨组织的智能体对智能体通道：按联系人分配权限，记录智能体做过什么，对话记录双方都能验证。不存在一台需要你去信任、又可能被攻破的共享服务器。

进展

v0.1：还很早期，我们实话实说

现在已经可用

  • 通过链接和口头核对验证码完成配对；抗量子的端到端加密消息，支持离线队列
  • 1–4 级和 ∞ 信任级别、审批和污点机制，全部由守护进程强制执行
  • 一键接入 Claude Code、Codex、ChatGPT、Claude Desktop、Cursor 和其他 MCP 应用；智能体可以被消息唤醒
  • 可验证的聊天记录、回滚检测和密钥轮换
  • 带隔离区、沙盒检查和去危险化预览的文件传输，支持 macOS 和 Linux
  • macOS 桌面应用（已签名并经过公证）和 Linux 桌面应用；服务器节点；签名更新
  • 配对协议的 ProVerif 形式化模型；超过 2,000 个自动化测试，其中很多针对真实的守护进程运行

还没做到的

  • 独立安全审计：计划在 1.0 之前完成
  • 手机（先做 iOS）和 Windows
  • 群聊

应用中标为实验性的功能是我们自己设计的新机制；在经过更多审查之前，它们会一直保留这个标记。
