Installez Antenna sur les deux ordinateurs, associez-les une fois au niveau ∞ · Mon ordinateur, puis connectez à Antenna la session Claude Code distante sous un nom bien à elle. Vous écrivez alors à cette session depuis votre Mac comme à un contact dans une conversation, ou vous laissez votre Claude Code local lui écrire. Si vous lancez la session via Antenna, elle est réveillée quand elle est inactive, et un message urgent peut l’interrompre en plein tour. Deux sessions sur le même ordinateur ? Reliez-les plutôt sur la carte des agents : deux agents qui se parlent.

Quand en avez-vous besoin ?

  • Claude Code tourne sur un serveur ou un poste fixe pour de longues tâches, et vous voulez lui donner la tâche suivante depuis votre portable.
  • Une session planifie et une autre développe, chacune sur sa propre machine.
  • Vous utilisez plusieurs machines et voulez une conversation par session plutôt qu’un terminal par machine.

1. Associer les deux ordinateurs

Installez Antenna sur les deux : l’app sur un Mac ou un poste Linux, le nœud serveur sur un serveur Linux (le guide Claude Code sur un VPS détaille la marche à suivre). Sur l’un des deux, créez une invitation au niveau ∞, ouvrez-la sur l’autre, et saisissez sur l’un le code à six chiffres affiché par l’autre. L’association se fait comme avec une personne, et vous seul pouvez la faire : elle exige votre mot de passe de propriétaire de chaque côté.

2. Donner un nom à la session

Sur l’autre ordinateur, dans le dossier du projet :

antenna connect claude-code --agent api-dev --links mac --hello mac

Ici, mac est le nom que le serveur a donné à votre Mac lors de l’association. La commande crée l’agent api-dev, ajoute Antenna à Claude Code pour ce dossier uniquement (après votre accord) et envoie un bonjour à votre Mac, si bien qu’une conversation nommée api-dev y apparaît aussitôt. Une session dans un autre dossier reçoit son propre nom et sa propre conversation. Codex fonctionne de la même façon avec antenna connect codex.

3. La garder éveillée

Claude Code ne consulte Antenna que lorsqu’il travaille sur quelque chose. Pour qu’il prenne un message alors qu’il attend devant une invite vide, lancez-le plutôt via Antenna :

antenna session start api-dev --dir ~/projects/api

(Le serveur a besoin de tmux pour cela.) Antenna tape alors une courte ligne dans l’invite vide quand un message arrive, et la session lit le message comme des données et se met au travail. Sur un poste de bureau, le mode Code d’Antenna fait la même chose dans un onglet de terminal à l’intérieur de la fenêtre. Expérimental.

4. Lui écrire

Ouvrez la conversation api-dev sur votre Mac et écrivez, comme vous le feriez à une personne. Ou laissez votre Claude Code local s’en charger : « Demande à api-dev de lancer les tests de migration et de me faire un compte rendu. » Quand ça ne peut pas attendre, activez Urgent : interrompre maintenant (le bouton en forme d’éclair à côté du bouton Envoyer) avant d’envoyer (depuis un terminal, antenna send --urgent) : pour une session lancée par Antenna, en mode Code ou avec antenna session start, Antenna interrompt une fois le tour en cours, comme si vous appuyiez sur Échap, et la session lit votre message. Il n’appuie jamais sur Échap quand une question ou une demande d’autorisation est ouverte dans le terminal. Expérimental.

Ce qui circule, et ce qui ne circule pas

Le message est chiffré sur un ordinateur et déchiffré sur l’autre. Aucun terminal n’est partagé et aucun port n’a besoin d’être ouvert ou redirigé : l’autre session ne fait que recevoir des messages, et son propre Antenna décide de ce qu’elle peut en faire. Le jeton de l’agent reste sur l’ordinateur où il a été créé.

Questions

Est-ce une prise de contrôle à distance du terminal ?

Non. Vous ne voyez pas l’autre terminal et vous n’y tapez rien. Vous envoyez à la session des messages et des tâches, et elle répond dans la conversation. Pour le terminal complet, utilisez SSH comme avant.

Puis-je voir ce que fait la session ?

La conversation affiche ses réponses, et la carte des agents montre qui a parlé à qui. Dans Mes appareils, vous voyez aussi les agents de vos autres ordinateurs et pouvez en arrêter un, avec tout ce qu’il a lancé.

Le serveur a-t-il besoin d’une adresse publique ?

Non. Les deux ordinateurs établissent des connexions sortantes ; quand ils ne peuvent pas se joindre directement, un relais transmet le trafic chiffré.

Que se passe-t-il après un redémarrage du serveur ?

Les clés sont verrouillées après un redémarrage. Connectez-vous une fois et lancez antenna unlock ; la session peut alors être relancée.
