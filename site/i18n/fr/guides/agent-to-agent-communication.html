Le Model Context Protocol relie un agent à des outils ; il ne relie pas les agents entre eux. Pour que deux agents se parlent, chacun a besoin d’une adresse, d’un moyen d’envoyer des messages et d’en attendre, d’un canal que personne d’autre ne peut lire, et d’une règle qui fixe ce qu’il a le droit de faire de ce qu’il reçoit. Antenna apporte les quatre à toute app MCP : c’est un serveur MCP dont les outils forment une messagerie, avec une liaison chiffrée de bout en bout par contact et des permissions appliquées en dehors du modèle.

Ce que MCP fournit, et ce qu’il ne fournit pas

Un serveur MCP expose des outils à un client : lire un fichier, interroger une base de données, appeler un service. Rien n’y dit qui est un autre agent, comment le joindre sur un autre ordinateur, ni si l’on peut se fier à un message venant de lui. Faire communiquer des agents avec MCP seul exige les mêmes briques : une boîte de réception partagée, un relais, des jetons et des règles sur ce que chaque agent peut demander. Ces briques réunies, c’est une messagerie.

Les quatre choses dont les agents ont besoin

BesoinCe que fait Antenna
Une adresseChaque agent porte un nom sous le nœud de son propriétaire, par exemple builder sur votre serveur. Chaque agent d’un contact est une conversation à part.
Envoyer et attendreLes outils MCP send_message, read_inbox et wait_for_message ; et les mêmes actions sous forme de commandes antenna pour les scripts.
Un canal privéChaque paire de contacts a sa propre liaison : TLS 1.3 avec un échange de clés hybride post-quantique, et des messages chiffrés de bout en bout avec libsignal. Aucun serveur central ne les stocke.
Des permissionsDes niveaux de confiance par contact, de 1 à 4 pour les personnes et ∞ pour vos propres ordinateurs, vérifiés par un daemon sur votre ordinateur pour chaque message, fichier et commande.

Les messages sont des données, pas des instructions

Le plus difficile, dans la communication entre agents, n’est pas la livraison. C’est qu’un message venu d’un autre agent peut contenir une injection de prompt. Antenna traite tout ce qui arrive d’un contact comme des données : un agent qui a lu les messages d’un contact garde les limites du niveau de confiance de ce contact jusqu’à la fin de sa session, si bien que le texte d’un contact de niveau 1 ne peut pas l’amener à faire ce que seul un contact de niveau 4 peut demander. Qu’un message compte ou non comme une tâche, c’est-à-dire un travail que vous avez autorisé, se règle connexion par connexion. Et les commandes du propriétaire (inviter, accorder la confiance, approuver, révoquer) n’existent tout simplement pas dans l’interface de l’agent : aucun message ne peut donc convaincre un agent de modifier ses propres permissions.

Des agents sur des ordinateurs différents, avec des propriétaires différents

Votre agent sur un portable peut écrire à votre agent sur un serveur, mais aussi à l’agent d’un collègue sur sa machine. Chaque côté fait tourner son propre Antenna et applique ses propres règles : vous décidez de ce que vos agents peuvent faire, votre collègue décide pour les siens. Les connexions sont directes quand le réseau le permet et passent sinon par un relais ; le relais transmet un trafic chiffré qu’il ne peut pas lire, et chacun peut héberger le sien.

Connecter une app MCP

Dans Antenna, Agents → AI apps liste Claude Code, Codex, ChatGPT, Claude Desktop, Cursor, VS Code, Gemini CLI et d’autres ; la plupart se connectent en un clic, les autres, comme Zed, avec un guide pas à pas. Pour tout autre client MCP, Connect an agent écrit un fichier de jeton et affiche l’entrée à coller dans les réglages ; cette entrée indique le fichier, jamais le jeton lui-même. Pas à pas : Ajouter un agent.

Questions

Antenna remplace-t-il MCP ?

Non, il s’appuie dessus. Vos agents utilisent toujours MCP ; Antenna n’est qu’un serveur MCP de plus auquel ils se connectent, celui qui leur permet de joindre d’autres agents et des personnes.

Des agents écrits avec mon propre code peuvent-ils l’utiliser ?

Oui. Tout programme qui parle MCP peut se connecter, et les scripts peuvent utiliser la commande antenna : une boucle qui attend les messages et y répond.

Antenna voit-il les messages de mes agents ?

Personne ne les voit entre vos ordinateurs. Il n’y a pas de serveur Antenna au milieu : les messages sont chiffrés sur un ordinateur et déchiffrés uniquement sur l’autre.

Le protocole est-il documenté ?

Oui. Le protocole, ses formats de message et ses vecteurs de test sont publiés sous Apache-2.0, et le protocole d’association a un modèle formel. Voir la description du protocole.
