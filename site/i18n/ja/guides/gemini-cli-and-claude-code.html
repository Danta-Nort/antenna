Gemini CLI をワンクリックで Antenna に接続し、Antenna のウィンドウで Claude Code を起動して、Antenna のエージェントマップで 2 つを線でつなぎます。それ以降は、どちらも Antenna の MCP ツールで相手にメッセージを送ります。Gemini CLI が Claude Code に変更のレビューを頼み、Claude Code が Gemini CLI にタスクを渡し、答えは同じ経路で返ってきます。どちらもいつもどおりあなた自身の Google と Claude のアカウントでサインインしたままで、API キーは不要です。

1 台のコンピューターで

  1. Antenna をインストール（macOS または Linux）してノードを作成します。必要なのはパスワード 1 つで、アカウントは要りません。
  2. エージェント → AI アプリ を開き、Gemini CLI の横の 接続 を押します。自分のプロジェクトにアクセスできるアシスタントを選んでパスワードを入力し、続ける を押します。Antenna が ~/.gemini/settings.json に追加する内容を確認して、書き込んで接続 を押します。Gemini CLI で /mcp reload を実行する（または起動し直す）と、/mcp に antenna が表示されます。アプリの行には「連絡先は gemini-cli 宛てに書きます」と表示されます。
  3. 同じページで、Claude Code の横の Code モードで起動 を押します。新しいエージェント… を選んで builder と名付け、同じロールの 自分のプロジェクトにアクセスできるアシスタント を選んでパスワードを入力し、起動 を押します。Claude Code はウィンドウ内のターミナルタブで動きます。
  4. エージェント → マップ を開き、一方のエージェントのハンドルからもう一方へドラッグして、パスワードを入力し 接続 を押します。2 つにはローカルルートが割り当てられ、メッセージはコンピューターの外に出ません。また、チェックを外さない限り、それぞれが相手のメッセージをタスクとして受け取ります。

2 つには同じロールを選んでください。Antenna は、あなたのデータをより多く見たエージェントが、それより少なく見たエージェントに書き込むことを許しません。

互いの呼び方

線を引くと、それぞれのエージェントにとって相手がデフォルトの相手役になります。「これを相手に送って」と言えば十分です。名前で指定するときは、エージェントが local_agent に gemini-cli または builder を指定して send_message を呼び出します。受け取る側は read_inbox で読むか、wait_for_message で待ちます（1 回の呼び出しで最大 10 分）。

2 つは待ち方が違います。Code モードの Claude Code は自分で目を覚まします。メッセージが届いたときに待機中なら、Antenna が受信箱を読むよう促す 1 行を代わりに入力します。実験的機能です。Antenna はまだ Gemini CLI を起こせないため、Gemini CLI は次に Antenna を呼び出したときにメッセージを読みます。そのため、やり取りを始めるのは Gemini CLI にするのが自然です。たとえば「builder に src/ の diff のレビューを頼んで、返事を待ってから、見つかった問題を直して」。Claude Code が目を覚まし、レビューして返信します。Gemini CLI に作業を渡すときは、まずメッセージを待つように伝えてください。

2 台のコンピューターで

Gemini CLI を 1 台のコンピューターに、Claude Code を別のコンピューターに置くこともできます。それぞれに Antenna をインストールし、招待リンクと 6 桁のコードで一度だけペアリングします。そのとき これは自分のコンピューターです（∞） にチェックを入れます。あとはマップで 2 つのエージェントの間に線を引くだけです。もう一方のコンピューターでも、そのコンピューター上か 自分のデバイス で承認を求められるので、あなたの知らないうちにそちらで何かが変わることはありません。画面のないサーバーでは、Claude Code を antenna connect claude-code と antenna session start で動かします。詳しくはVPS で Claude Code を動かすをご覧ください。

あなたが承認するもの、制限が残るもの

  • 接続を決めるのはあなたです。線を引くにはパスワードが必要で、エージェントが接続を作ったり変えたりすることはできません。
  • Antenna がすべてのメッセージを検査します。同じコンピューター上の 2 つのエージェントの間では、鍵、パスワード、トークンを含んでいそうなメッセージは拒否されます。また、10 分以内に 8 通のメッセージが続くとそのやり取りは止まるので、2 つが永遠に互いを忙しくさせることはできません。
  • 信頼レベルは、エージェントが読んだものについて回ります。同じコンピューター上で、一方のエージェントがある連絡先のメッセージを読んでいた場合、そのエージェントのメッセージにはその連絡先の制限が付いてもう一方に届き、受け取った側も自分で読んだのと同じように制限されます。
  • Claude Code はツールを使うたびに確認されます。Code モードでは、Antenna はすべてのコマンドと編集の前に自分のデーモンに確認します。Gemini CLI 自身のツールは、これまでどおり Gemini CLI 自身の確認の仕組みで管理されます。Antenna が検査するのは、Antenna を通るものです。

よくある質問

Gemini の API キーは必要ですか？

いいえ。Gemini CLI はいつもどおり Google アカウントで、Claude Code は Claude のプランでサインインします。Antenna はメッセージを運ぶだけです。

2 つの Gemini CLI ウィンドウで同時に Antenna を使えますか？

一度に 1 つだけです。エージェントが同時に作業できるのは 1 つのセッションだけで、接続 で Gemini CLI に割り当てられるエージェントは 1 つです。

この機能は完成していますか？

マップでのエージェントの接続と待機中のエージェントの起動は、Antenna 0.1 では実験的機能とされています。動作し、テストもされていますが、今後変わる可能性があります。
