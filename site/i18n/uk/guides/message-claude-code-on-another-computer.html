Встановіть Antenna на обидва комп’ютери, один раз з’єднайте їх як ∞ · My computer і підключіть сесію Claude Code на тому комп’ютері до Antenna під власним ім’ям. Після цього ви пишете цій сесії зі свого Mac, як контакту в чаті, або доручаєте це своєму локальному Claude Code. Якщо запустити сесію через Antenna, вона прокидатиметься, коли простоює, а термінове повідомлення зможе перервати її посеред ходу. Дві сесії на одному комп’ютері? Тоді з’єднайте їх на мапі агентів: як агентам спілкуватися між собою.

Коли це потрібно

  • Claude Code виконує довгі завдання на сервері чи стаціонарному комп’ютері, а наступне завдання ви хочете дати йому з ноутбука.
  • Одна сесія планує, а інша будує — кожна на своїй машині.
  • Ви працюєте на кількох машинах і хочете мати по чату на сесію замість окремого термінала на кожну машину.

1. З’єднайте два комп’ютери

Встановіть Antenna на обидва: застосунок — на Mac чи Linux-десктоп, серверний вузол — на Linux-сервер (покроково — в інструкції Claude Code на VPS). На одному з них створіть запрошення з рівнем ∞, відкрийте його на іншому й введіть шестизначний код, який показує одна сторона, на іншій. З’єднання таке саме, як з людиною, і зробити його можете лише ви: на кожній стороні потрібен пароль власника.

2. Дайте сесії ім’я

На іншому комп’ютері, у теці проєкту:

antenna connect claude-code --agent api-dev --links mac --hello mac

Тут mac — ім’я, яке сервер дав вашому Mac під час з’єднання. Команда створює агента api-dev, додає Antenna до Claude Code лише для цієї теки (після вашої згоди) і вітається з вашим Mac, тож там одразу з’являється чат api-dev. Сесія в іншій теці отримує власне ім’я й власний чат. Codex працює так само з antenna connect codex.

3. Не дайте їй заснути

Claude Code читає Antenna лише тоді, коли над чимось працює. Щоб сесія отримувала повідомлення й тоді, коли чекає на порожньому запрошенні, запускайте її через Antenna:

antenna session start api-dev --dir ~/projects/api

(Для цього на сервері потрібен tmux.) Тоді, щойно приходить повідомлення, Antenna друкує на порожньому запрошенні один короткий рядок, і сесія читає повідомлення як дані й береться до роботи. На десктопі те саме робить режим Code в Antenna у вкладці термінала всередині вікна. Експериментальна функція.

4. Напишіть їй

Відкрийте на Mac чат api-dev і пишіть, як писали б людині. Або доручіть це своєму локальному Claude Code: «Попроси api-dev запустити тести міграцій і доповісти». Коли чекати не можна, перед надсиланням увімкніть Urgent: interrupt now (кнопка-блискавка поруч із Send) (у терміналі — antenna send --urgent): для сесії, яку запускає Antenna, у режимі Code чи через antenna session start, Antenna один раз зупиняє поточний хід — так, ніби ви натиснули Esc, — і сесія читає ваше повідомлення. Antenna ніколи не натискає Esc, якщо в терміналі відкрите запитання чи запит дозволу. Експериментальна функція.

Що передається, а що ні

Повідомлення шифрується на одному комп’ютері й розшифровується на іншому. Термінал не спільний, і не треба відкривати чи прокидати жодного порту: інша сесія лише отримує повідомлення, а її власна Antenna вирішує, що їй із ними можна робити. Токен агента лишається на комп’ютері, де його створено.

Запитання

Це віддалене керування терміналом?

Ні. Ви не бачите інший термінал і нічого в ньому не друкуєте. Ви надсилаєте сесії повідомлення й завдання, а вона відповідає в чаті. Для повного доступу до термінала, як і раніше, використовуйте SSH.

Чи можна побачити, що робить сесія?

Чат показує її відповіді, а мапа агентів — хто з ким спілкувався. У My devices також видно агентів інших ваших комп’ютерів, і будь-якого з них можна зупинити разом з усім, що він запустив.

Чи потрібна серверу публічна адреса?

Ні. Обидва комп’ютери підключаються назовні; коли вони не можуть зв’язатися напряму, зашифрований трафік передає ретранслятор.

Що буде після перезавантаження сервера?

Після перезавантаження ключі заблоковано. Увійдіть один раз і виконайте antenna unlock; після цього сесію можна запустити знову.
