ثبّت Antenna على الحاسوبين، واقرنهما مرة واحدة بمستوى ∞ · My computer، واربط جلسة Claude Code هناك بـ Antenna باسم خاص بها. بعدها تكتب إلى تلك الجلسة من جهاز Mac كما تكتب إلى جهة اتصال في محادثة، أو تدع Claude Code المحلي يكتب إليها. وإن شغّلت الجلسة عبر Antenna، فإنها تُوقَظ حين تكون خاملة، ويمكن لرسالة عاجلة أن تقاطعها في منتصف دورها. جلستان على الحاسوب نفسه؟ اربط بينهما على خريطة الوكلاء بدلًا من ذلك: وكيلان يتحدثان.

متى تحتاج إلى هذا

  • يعمل Claude Code على خادم أو حاسوب مكتبي لمهام طويلة، وتريد أن تعطيه المهمة التالية من حاسوبك المحمول.
  • جلسة تخطط وأخرى تبني، كل منهما على جهازها.
  • تستخدم عدة أجهزة وتريد محادثة واحدة لكل جلسة بدلًا من طرفية لكل جهاز.

1. اقرن الحاسوبين

ثبّت Antenna على الاثنين: التطبيق على جهاز Mac أو حاسوب Linux مكتبي، وعقدة الخادم على خادم Linux (يشرح ذلك دليل Claude Code على خادم VPS). على أحدهما أنشئ دعوة بالمستوى ∞، وافتحها على الآخر، وأدخل الرمز المكوّن من ستة أرقام الذي يعرضه أحد الطرفين في الطرف الآخر. الاقتران هو نفسه كما مع أي شخص، ولا يستطيع أحد غيرك القيام به: فهو يتطلب كلمة مرور المالك على كل طرف.

2. امنح الجلسة اسمًا

على الحاسوب الآخر، في مجلد المشروع:

antenna connect claude-code --agent api-dev --links mac --hello mac

هنا mac هو الاسم الذي أعطاه الخادم لجهاز Mac عند الاقتران. ينشئ هذا الوكيل api-dev، ويضيف Antenna إلى Claude Code لهذا المجلد فقط (بعد موافقتك)، ويلقي التحية على جهاز Mac، فتظهر هناك فورًا محادثة باسم api-dev. والجلسة في مجلد آخر تحصل على اسمها ومحادثتها الخاصين. ويعمل Codex بالطريقة نفسها مع antenna connect codex.

3. أبقها مستيقظة

لا يقرأ Claude Code ما في Antenna إلا أثناء عمله على شيء ما. ولكي يلتقط رسالة وهو أمام موجّه فارغ، شغّله عبر Antenna بدلًا من ذلك:

antenna session start api-dev --dir ~/projects/api

(يحتاج الخادم إلى tmux لهذا.) عندها يكتب Antenna سطرًا قصيرًا واحدًا عند الموجّه الفارغ حين تصل رسالة، فتقرأ الجلسة الرسالة كبيانات وتباشر العمل. وعلى الحاسوب المكتبي، يفعل وضع Code في Antenna الشيء نفسه في علامة تبويب طرفية داخل النافذة. تجريبي.

4. اكتب إليها

افتح محادثة api-dev على جهاز Mac واكتب، كما تكتب إلى شخص. أو دع Claude Code المحلي يفعل ذلك: «اطلب من api-dev تشغيل اختبارات الترحيل (migration) وإبلاغي بالنتيجة». وحين لا يحتمل الأمر الانتظار، فعّل Urgent: interrupt now (زر البرق بجوار Send) قبل الإرسال (ومن الطرفية: antenna send --urgent): فللجلسة التي يشغّلها Antenna، في وضع Code أو عبر antenna session start، يوقف Antenna الدور الجاري مرة واحدة، كما لو ضغطت Esc، فتقرأ الجلسة رسالتك. ولا يضغط Esc أبدًا فوق سؤال أو طلب إذن مفتوح في الطرفية. تجريبي.

ما ينتقل وما لا ينتقل

تُشفَّر الرسالة على حاسوب ويُفك تشفيرها على الآخر. لا تُشارَك أي طرفية، ولا يلزم فتح أي منفذ أو إعادة توجيهه: الجلسة الأخرى تستقبل الرسائل فقط، ونسخة Antenna لديها هي التي تقرر ما يحق لها فعله بها. ويبقى رمز وصول الوكيل على الحاسوب الذي أُنشئ عليه.

أسئلة

هل هذا تحكم عن بُعد في الطرفية؟

لا. لا ترى الطرفية الأخرى ولا تكتب فيها. ترسل إلى الجلسة رسائل ومهام، فتجيب في المحادثة. وللطرفية الكاملة، استخدم SSH كما من قبل.

هل يمكنني رؤية ما تفعله الجلسة؟

تعرض المحادثة ردودها، وتعرض خريطة الوكلاء من تحدث مع من. وفي My devices يمكنك أيضًا رؤية وكلاء حواسيبك الأخرى وإيقاف أحدهم مع كل ما شغّله.

هل يحتاج الخادم إلى عنوان عام؟

لا. يتصل الحاسوبان نحو الخارج؛ وحين لا يستطيعان الوصول إلى بعضهما مباشرة، يمرر خادم ترحيل (relay) حركة المرور المشفرة.

ماذا يحدث بعد إعادة تشغيل الخادم؟

تُقفل المفاتيح بعد إعادة التشغيل. سجّل الدخول مرة واحدة وشغّل antenna unlock، ثم يمكن تشغيل الجلسة من جديد.
