اربط Gemini CLI بـ Antenna بنقرة واحدة، وشغّل Claude Code في نافذة Antenna، ثم ارسم خطًا بينهما على خريطة الوكلاء في Antenna. ومن تلك اللحظة يكتب كل منهما إلى الآخر بأدوات MCP في Antenna: يطلب Gemini CLI من Claude Code مراجعة تعديل، ويسلّم Claude Code مهمة إلى Gemini CLI، ويعود الجواب بالطريقة نفسها. ويبقى كل منهما مسجّلًا بحسابيك أنت في Google وClaude، بلا مفاتيح API.

على حاسوب واحد

  1. ثبّت Antenna ‏(macOS أو Linux) وأنشئ عقدتك: كلمة مرور واحدة، بلا حساب.
  2. افتح Agents → AI apps واضغط Connect بجوار Gemini CLI. اختر Assistant with access to my projects (مساعد يصل إلى مشاريعي)، وأدخل كلمة المرور، واضغط Continue، واقرأ ما سيضيفه Antenna إلى ~/.gemini/settings.json، ثم اضغط Write and connect. في Gemini CLI شغّل /mcp reload (أو أعد تشغيله): سيظهر antenna في قائمة /mcp. ويظهر في صفه في التطبيق «Contacts write to it as gemini-cli»، أي أن جهات الاتصال تراسله باسم gemini-cli.
  3. في الصفحة نفسها، اضغط Start in Code mode بجوار Claude Code. اختر New agent…، وسمّه builder، واختر الدور نفسه، Assistant with access to my projects، وأدخل كلمة المرور واضغط Start. يعمل Claude Code في علامة تبويب طرفية داخل النافذة.
  4. افتح Agents → Map، واسحب من مقبض أحد الوكيلين إلى الآخر، وأدخل كلمة المرور واضغط Connect. يحصل الاثنان على مسار محلي: لا تغادر رسائلهما الحاسوب أبدًا، ويتلقى كل منهما رسائل الآخر كمهام ما لم تُلغِ تحديد هذا الخيار.

امنح الاثنين الدور نفسه: لا يسمح Antenna لوكيل اطّلع على قدر أكبر من بياناتك بأن يكتب إلى وكيل اطّلع على قدر أقل.

كيف يخاطب كل منهما الآخر

بعد رسم الخط يصبح كل وكيل الطرف الافتراضي للآخر: تكفي عبارة «أرسل هذا إلى نظيرك». ولتسمية الطرف الآخر صراحةً، يستدعي الوكيل send_message مع ضبط local_agent على gemini-cli أو builder. ويقرأ الطرف المستقبِل بـ read_inbox، أو ينتظر بـ wait_for_message مدة تصل إلى 10 دقائق في كل استدعاء.

ولكل منهما طريقته في الانتظار. فـ Claude Code في وضع Code يستيقظ وحده: إذا وصلت رسالة وهو خامل، يكتب Antenna سطرًا واحدًا يطلب منه قراءة صندوق الوارد. تجريبي. أما Gemini CLI فلا يوقظه Antenna بعد، لذا يقرأ رسائله عندما يستدعي Antenna في المرة التالية. ولهذا يكون Gemini CLI هو الأنسب لبدء التبادل: «اطلب من builder مراجعة الـ diff في src/، ثم انتظر جوابه وأصلح ما يجده». فيستيقظ Claude Code ويراجع ويرد. ولتسليم Gemini CLI عملًا، اطلب منه أولًا أن ينتظر الرسائل.

على حاسوبين

يمكن أن يبقى Gemini CLI على حاسوب وClaude Code على حاسوب آخر. ثبّت Antenna على كل منهما واقرنهما مرة واحدة برابط دعوة ورمز من ستة أرقام، مع تحديد This is my own computer (∞). ثم ارسم الخط بين الوكيلين على الخريطة. يطلب منك الحاسوب الآخر الموافقة على طرفه، هناك أو في My devices، فلا يتغير شيء هناك دون علمك. وعلى خادم بلا شاشة، يعمل Claude Code عبر antenna connect claude-code وantenna session start: انظر Claude Code على خادم VPS.

ما توافق عليه أنت، وما يبقى مقيّدًا

  • الاتصالات بيدك. رسم الخط يتطلب كلمة مرورك، ولا يستطيع أي وكيل إنشاء اتصال أو تغييره.
  • يفحص Antenna كل رسالة. بين وكيلين على حاسوب واحد، تُرفض الرسالة التي يبدو أنها تحمل مفتاحًا أو كلمة مرور أو رمز وصول، وتتوقف السلسلة بعد 8 رسائل خلال 10 دقائق، فلا يستطيع الاثنان إشغال أحدهما الآخر إلى الأبد.
  • مستويات الثقة تتبع ما قرأه الوكيل. على حاسوب واحد، إذا قرأ أحد الوكيلين رسالة من جهة اتصال، فإن رسالته تحمل قيود تلك الجهة إلى الوكيل الآخر، فيُقيَّد هذا بدوره كأنه قرأها بنفسه.
  • يُفحص Claude Code قبل كل أداة. في وضع Code يسأل Antenna خدمته الخلفية قبل كل أمر وكل تعديل. أما أدوات Gemini CLI نفسه فتبقى خاضعة لتأكيدات Gemini CLI نفسه، ويفحص Antenna ما يمر عبره.

أسئلة

هل يحتاج هذا إلى مفتاح Gemini API؟

لا. يسجّل Gemini CLI الدخول بحسابك في Google، وClaude Code باشتراكك في Claude، كما هو الحال دائمًا. وAntenna ينقل الرسائل فقط.

هل يمكن لنافذتين من Gemini CLI استخدام Antenna في الوقت نفسه؟

واحدة في كل مرة: يعمل الوكيل في جلسة واحدة في كل مرة، وConnect يمنح Gemini CLI وكيلًا واحدًا.
