클릭 한 번으로 Gemini CLI를 Antenna에 연결하고, Antenna 창에서 Claude Code를 시작한 다음, Antenna의 에이전트 맵에서 둘 사이에 선을 그으세요. 그때부터 둘은 Antenna의 MCP 도구로 서로에게 메시지를 보내요. Gemini CLI가 Claude Code에게 변경 사항 리뷰를 부탁하고, Claude Code가 Gemini CLI에게 작업을 넘기고, 답은 같은 길로 돌아와요. 둘 다 평소처럼 내 Google과 Claude 계정으로 로그인한 채 쓰고, API 키는 필요 없어요.

한 컴퓨터에서

  1. Antenna를 설치하고(macOS 또는 Linux) 노드를 만드세요. 비밀번호 하나면 되고, 계정은 없어요.
  2. 에이전트 → AI 앱을 열고 Gemini CLI 옆의 연결을 누르세요. 내 프로젝트에 접근하는 어시스턴트를 고르고, 비밀번호를 입력한 뒤 계속을 누르세요. Antenna가 ~/.gemini/settings.json에 무엇을 추가할지 읽어 보고 쓰고 연결을 누르세요. Gemini CLI에서 /mcp reload를 실행하면(또는 다시 시작하면) /mcp 목록에 antenna가 보여요. 앱 목록의 그 줄에는 “연락처는 gemini-cli(이)라는 이름으로 메시지를 보내요”라고 나와요.
  3. 같은 페이지에서 Claude Code 옆의 Code 모드로 시작을 누르세요. 새 에이전트…를 고르고 이름을 builder로 정한 뒤, 같은 역할인 내 프로젝트에 접근하는 어시스턴트를 고르고 비밀번호를 입력한 다음 시작을 누르세요. Claude Code는 창 안의 터미널 탭에서 돌아가요.
  4. 에이전트 → 맵을 열고 한 에이전트의 핸들에서 다른 에이전트로 끌어다 놓은 뒤, 비밀번호를 입력하고 연결을 누르세요. 둘은 로컬 경로로 연결돼서 메시지가 컴퓨터 밖으로 절대 나가지 않고, 체크를 해제하지 않는 한 서로의 메시지를 작업으로 받아요.

둘에게 같은 역할을 주세요. Antenna는 내 데이터를 더 많이 본 에이전트가 덜 본 에이전트에게 쓰는 걸 허락하지 않아요.

서로를 부르는 방법

선을 그으면 두 에이전트는 서로의 기본 상대가 돼요. “이걸 상대에게 보내 줘”라고만 해도 충분해요. 이름으로 지정하려면 에이전트가 local_agent를 gemini-cli나 builder로 정해서 send_message를 호출해요. 받는 쪽은 read_inbox로 읽거나, wait_for_message로 한 번 호출할 때마다 최대 10분까지 기다려요.

둘은 기다리는 방식이 달라요. Code 모드의 Claude Code는 알아서 깨어나요. 쉬고 있을 때 메시지가 오면 Antenna가 수신함을 읽으라는 한 줄을 대신 입력해 줘요. 실험적 기능이에요. Antenna는 아직 Gemini CLI를 깨우지 못해서, Gemini CLI는 다음에 Antenna를 호출할 때 메시지를 읽어요. 그래서 대화는 Gemini CLI가 시작하는 게 자연스러워요. 예를 들어 “builder에게 src/의 diff를 리뷰해 달라고 하고, 답을 기다렸다가 찾은 문제를 고쳐 줘.” 그러면 Claude Code가 깨어나서 리뷰하고 답해요. Gemini CLI에게 작업을 넘기려면 먼저 메시지를 기다리라고 말해 두세요.

두 컴퓨터에서

Gemini CLI는 한 컴퓨터에, Claude Code는 다른 컴퓨터에 둘 수도 있어요. 컴퓨터마다 Antenna를 설치하고, 초대 링크와 여섯 자리 코드로 한 번 페어링하면서 내 컴퓨터예요(∞)에 체크하세요. 그런 다음 맵에서 두 에이전트 사이에 선을 그으세요. 다른 컴퓨터는 그 컴퓨터에서나 내 기기에서 그쪽 연결을 승인해 달라고 물어보니, 내가 모르게 바뀌는 건 없어요. 화면 없는 서버에서는 Claude Code를 antenna connect claude-code와 antenna session start로 실행해요. VPS에서 Claude Code 돌리기를 참고하세요.

내가 승인하는 것, 제한이 남는 것

  • 연결은 내가 정해요. 선을 그으려면 내 비밀번호가 필요하고, 어떤 에이전트도 연결을 만들거나 바꿀 수 없어요.
  • Antenna가 모든 메시지를 확인해요. 한 컴퓨터의 두 에이전트 사이에서는 키, 비밀번호, 토큰이 들어 있는 것 같은 메시지를 거부하고, 10분 안에 메시지가 8개 오가면 체인이 멈춰서 둘이 끝없이 서로를 붙잡고 있을 수 없어요.
  • 신뢰 레벨은 에이전트가 읽은 것을 따라가요. 한 컴퓨터에서 한 에이전트가 어떤 연락처의 메시지를 읽었다면, 그 에이전트가 보내는 메시지에는 그 연락처의 제한이 함께 붙어 가고, 받은 에이전트도 직접 읽은 것처럼 제한을 받아요.
  • Claude Code는 도구를 쓸 때마다 확인을 거쳐요. Code 모드에서 Antenna는 모든 명령과 편집 전에 자기 데몬에게 물어봐요. Gemini CLI 자체 도구는 계속 Gemini CLI 자체 확인 절차를 따르고, Antenna는 자기를 거쳐 가는 것을 확인해요.

자주 묻는 질문

Gemini API 키가 필요한가요?

아니요. Gemini CLI는 평소처럼 내 Google 계정으로, Claude Code는 내 Claude 요금제로 로그인해요. Antenna는 메시지만 실어 날라요.

Gemini CLI 창 두 개가 동시에 Antenna를 쓸 수 있나요?

한 번에 하나만 돼요. 에이전트는 한 번에 한 세션에서만 일하고, 연결은 Gemini CLI에 에이전트 하나를 줘요.

완성된 기능인가요?

맵에서 에이전트를 연결하는 기능과 쉬고 있는 에이전트를 깨우는 기능은 Antenna 0.1에서 실험적 기능으로 표시돼 있어요. 동작하고 테스트도 거쳤지만, 아직 바뀔 수 있어요.
