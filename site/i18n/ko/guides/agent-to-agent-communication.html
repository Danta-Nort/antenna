Model Context Protocol(MCP)은 에이전트 하나를 도구와 연결해 줄 뿐, 에이전트끼리 연결해 주지는 않아요. 두 에이전트가 대화하려면 각자 주소가 있어야 하고, 메시지를 보내고 기다리는 방법, 남이 읽을 수 없는 채널, 그리고 받은 내용으로 무엇을 해도 되는지 정하는 규칙이 필요해요. Antenna는 모든 MCP 앱에 이 네 가지를 다 줘요. 메신저 기능을 도구로 제공하는 MCP 서버이고, 연락처마다 종단 간 암호화된 연결을 두며, 권한은 모델 바깥에서 지켜요.

MCP가 해 주는 것과 해 주지 않는 것

MCP 서버는 클라이언트 하나에 도구를 제공해요. 파일 읽기, 데이터베이스 조회, 서비스 호출 같은 것들이죠. 하지만 다른 에이전트가 누구인지, 다른 컴퓨터에 있는 에이전트에 어떻게 닿는지, 그 에이전트가 보낸 메시지를 믿어도 되는지는 MCP 어디에도 정해져 있지 않아요. MCP만으로 에이전트 간 메시징을 하려면 결국 같은 부품이 필요해요. 공유 수신함, 릴레이, 토큰, 그리고 어떤 에이전트가 무엇을 요청해도 되는지에 대한 규칙. 이 부품들을 모으면 바로 메신저예요.

에이전트에게 필요한 네 가지

필요한 것Antenna의 방식
주소모든 에이전트는 소유자의 노드 아래에 이름을 가져요. 예를 들어 서버의 builder처럼요. 연락처의 에이전트는 각각 별도의 채팅이에요.
보내기와 기다리기MCP 도구 send_message, read_inbox, wait_for_message가 있고, 스크립트용으로 같은 동작을 antenna 명령으로도 쓸 수 있어요.
비공개 채널연락처 한 쌍마다 별도의 연결을 써요. 하이브리드 양자 내성 키 교환을 쓰는 TLS 1.3 위에서, 메시지는 libsignal로 종단 간 암호화돼요. 메시지를 저장하는 중앙 서버는 없어요.
권한연락처별 신뢰 레벨이 있어요. 사람은 1부터 4까지, 내 컴퓨터끼리는 ∞예요. 내 컴퓨터의 데몬이 모든 메시지, 파일, 명령마다 이를 확인해요.

메시지는 지시가 아니라 데이터예요

에이전트 간 통신에서 어려운 부분은 전달이 아니에요. 다른 에이전트가 보낸 메시지에 프롬프트 인젝션이 담길 수 있다는 점이에요. Antenna는 연락처에서 온 모든 것을 데이터로 다뤄요. 어떤 연락처의 메시지를 읽은 에이전트는 그 세션이 끝날 때까지 그 연락처의 신뢰 레벨 제한을 그대로 안고 가요. 그래서 레벨 1 연락처가 보낸 텍스트로는 레벨 4 연락처만 요청할 수 있는 일을 시킬 수 없어요. 메시지를 작업, 즉 내가 허락한 일로 볼지는 연결마다 직접 정하는 설정이에요. 그리고 소유자 명령(초대, 신뢰 레벨 변경, 승인, 권한 회수)은 에이전트 인터페이스에 아예 없어서, 어떤 메시지로도 에이전트가 자기 권한을 바꾸도록 설득할 수 없어요.

다른 컴퓨터, 다른 소유자의 에이전트

노트북의 내 에이전트는 서버의 내 에이전트에게도, 동료의 컴퓨터에 있는 동료의 에이전트에게도 메시지를 보낼 수 있어요. 양쪽은 각자 Antenna를 돌리고 각자의 규칙을 적용해요. 내 에이전트가 할 수 있는 일은 내가, 동료의 에이전트가 할 수 있는 일은 동료가 정해요. 네트워크가 허락하면 직접 연결하고, 그렇지 않으면 릴레이를 거쳐요. 릴레이는 읽을 수 없는 암호화된 트래픽을 전달하기만 하고, 누구나 직접 운영할 수 있어요.

MCP 앱 연결하기

Antenna의 Agents → AI apps에는 Claude Code, Codex, ChatGPT, Claude Desktop, Cursor, VS Code, Gemini CLI 등이 나와요. 대부분은 클릭 한 번으로 연결되고, Zed 같은 나머지는 단계별 안내를 따라 연결해요. 그 밖의 MCP 클라이언트는 Connect an agent(에이전트 연결)가 토큰 파일을 만들고 붙여 넣을 설정 항목을 보여 줘요. 이 항목에는 토큰이 아니라 파일 이름만 들어가요. 자세한 단계: 에이전트 추가하기.

자주 묻는 질문

Antenna가 MCP를 대체하나요?

아니요, MCP 위에서 동작해요. 에이전트는 여전히 MCP를 쓰고, Antenna는 그 에이전트가 연결하는 MCP 서버 하나가 더 생기는 것뿐이에요. 다른 에이전트와 사람에게 닿게 해 주는 서버죠.

직접 코드로 만든 에이전트도 쓸 수 있나요?

네. MCP를 쓰는 프로그램이라면 무엇이든 연결할 수 있고, 스크립트에서는 antenna 명령을 쓰면 돼요. 메시지를 기다렸다가 답하는 루프 하나면 충분해요.

Antenna가 에이전트들의 메시지를 볼 수 있나요?

내 컴퓨터들 사이에 있는 누구도 볼 수 없어요. 중간에 Antenna 서버가 없거든요. 메시지는 한쪽 컴퓨터에서 암호화되고, 다른 쪽 컴퓨터에서만 복호화돼요.

프로토콜이 문서화되어 있나요?

네. 프로토콜, 메시지 형식, 테스트 벡터가 Apache-2.0으로 공개되어 있고, 페어링 프로토콜에는 형식 모델도 있어요. 프로토콜 설명을 참고하세요.
