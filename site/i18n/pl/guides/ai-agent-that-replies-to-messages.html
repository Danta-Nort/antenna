W Antennie możesz wybrać kontakt i agenta (Claude Code, Codex albo własne polecenie), a od tej chwili każda wiadomość od tego kontaktu uruchamia agenta, który ją czyta i odpowiada. Antenna uruchamia go w piaskownicy (sandbox), z uprawnieniami nie większymi niż poziom zaufania tego kontaktu, a druga osoba widzi odpowiedź na bieżąco, w miarę jak powstaje. Agent działa na twoim własnym logowaniu do Claude albo ChatGPT, a odpowiedź, która wygląda, jakby zawierała sekret, czeka na twoją zgodę.

Typowe zastosowania

  • Twój własny asystent na serwerze. Piszesz do serwera z laptopa, a Claude Code na serwerze odpowiada, buduje projekt i uruchamia w nim testy.
  • Recepcja dla kontaktu. Pytania kolegi o twój projekt od razu dostają odpowiedź od agenta, który widzi tylko folder tej rozmowy.
  • Skrypt, który raportuje. Wynik dowolnego programu można wysłać jako strumień na żywo: my-program | antenna send --stream <contact>.

Ustawienie w oknie aplikacji

  1. Na komputerze, na którym ma działać agent, otwórz Agents → Set up for a contact… (albo w rozmowie, na karcie kontaktu, Agent replies → Set up…).
  2. Wybierz kontakt i program: Claude Code, Codex albo własne polecenie.
  3. Opcjonalnie wklej długoterminowy token logowania (z claude setup-token) w pole Value (optional). Trafia on raz do twojego węzła i jest przechowywany w jego zaszyfrowanej bazie danych. Na Macu to niezawodny sposób, bo piaskownica nie ma dostępu do pęku kluczy.
  4. Potwierdź hasłem właściciela. Reguła, jej ostatnie uruchomienie i Run log (dziennik uruchomień) pojawią się w Agents.

W terminalu to jedna linia: antenna wake set <contact> --cmd "claude -p --output-format stream-json". antenna wake list pokazuje reguły i ostatnie uruchomienia, a antenna wake off <contact> wyłącza regułę.

Co agent może, a czego nie

  • Jego prompt jest stały: „masz nową wiadomość, przeczytaj ją i odpowiedz”. Sama wiadomość nigdy nie staje się promptem; agent czyta ją jako dane, z uprawnieniami nie większymi niż poziom zaufania kontaktu.
  • Działa w piaskownicy (bubblewrap albo Landlock na Linuksie, Seatbelt na macOS): widzi swój folder tymczasowy i folder tej rozmowy, a z sieci dociera tylko do dostawcy swojego modelu. Twoje projekty, pozostałe pliki i klucze węzła są poza jego zasięgiem. Bez piaskownicy Antenna go nie uruchomi.
  • Każde uruchomienie zaczyna się od zera, chyba że ustawisz agenta jako stałego (o tym niżej), więc wcześniejsza wiadomość nie zostawi instrukcji dla późniejszego uruchomienia.
  • Limity: limit czasu na jedno uruchomienie i limit uruchomień na godzinę, więc gadatliwy kontakt nie wyczerpie twojego limitu użycia.

Praca w twoim projekcie

Tylko dla twoich własnych komputerów (∞) agent może też pracować w jednym folderze projektu z twoimi narzędziami: --project ~/code/payments, do tego foldery tylko do odczytu w --tool-path i rejestry pakietów, do których może sięgać, w --allow-host. Dla każdego innego kontaktu Antenna odmówi, a twojego folderu domowego, własnych danych ani folderów z sekretami, takich jak ~/.ssh, nie otworzy nigdy.

Pytania

Czy druga osoba widzi odpowiedź w trakcie pisania?

Tak, w przypadku kontaktów od poziomu 3 wzwyż: dymek rośnie na żywo, gdy agent pisze, a na końcu staje się zwykłą wiadomością. Poziomy 1 i 2 dostają gotową odpowiedź.

Co, jeśli agent wpisze do odpowiedzi hasło albo klucz?

Strumień do drugiej osoby się zatrzymuje, a wiadomość czeka na twoją zgodę. Dalej idzie tylko do twoich własnych komputerów.

Czy agent pamięta wcześniejsze rozmowy?

Domyślnie nie: każda wiadomość uruchamia go od nowa. Do pracy, która trwa godzinami, dodaj --resident: ta sama sesja Claude Code zostaje wtedy przy rozmowie, pamięta, co zostało powiedziane i ustalone, a każda nowa wiadomość staje się jej kolejną turą. Wiadomości nadal docierają do niej jako dane od drugiej strony.
