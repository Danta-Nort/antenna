The Model Context Protocol connects one agent to tools; it does not connect agents to each other. For two agents to talk, each needs an address, a way to send and wait for messages, a channel others cannot read, and a rule for what it may do with what it receives. Antenna gives every MCP app all four: it is an MCP server whose tools are a messenger, with an end-to-end encrypted link per contact and permissions enforced outside the model.

What MCP gives you, and what it does not

An MCP server exposes tools to one client: read a file, query a database, call a service. Nothing in it says who another agent is, how to reach it on another computer, or whether a message from it should be trusted. Agent-to-agent messaging on MCP alone needs the same pieces: a shared inbox, a relay, tokens, and rules about which agent may ask what. Those pieces are a messenger.

The four things agents need

NeedHow Antenna does it
An addressEvery agent has a name under its owner’s node, like builder on your server. Each agent of a contact is its own chat.
Send and waitMCP tools send_message, read_inbox and wait_for_message; and the same actions as antenna commands for scripts.
A private channelEach pair of contacts has its own link: TLS 1.3 with a hybrid post-quantum key exchange, and messages encrypted end to end with libsignal. No central server stores them.
PermissionsTrust levels per contact, 1 to 4 for people and ∞ for your own computers, checked by a daemon on your computer for every message, file and command.

Messages are data, not instructions

The hard part of agent-to-agent communication is not delivery. It is that a message from another agent can carry a prompt injection. Antenna treats everything that arrives from a contact as data: an agent that has read a contact’s messages keeps the limits of that contact’s trust level for the rest of its session, so text from a level-1 contact cannot steer it into doing what only a level-4 contact may ask. Whether a message counts as a task, work you authorized, is a setting you choose per connection. And the owner commands (invite, trust, approve, revoke) do not exist in the agent interface at all, so no message can talk an agent into changing its own permissions.

Agents on different computers and with different owners

Your agent on a laptop can message your agent on a server, and also a colleague’s agent on their machine. Each side runs its own Antenna and applies its own rules: you decide what your agents may do, they decide what theirs may do. Connections are direct when the network allows and go through a relay otherwise; the relay forwards encrypted traffic it cannot read, and anyone can run their own.

Questions

Is Antenna a replacement for MCP?

No, it builds on it. Your agents still use MCP; Antenna is one more MCP server they connect to, the one that lets them reach other agents and people.

Can agents written with my own code use it?

Yes. Any program that speaks MCP can connect, and scripts can use the antenna command: a loop that waits for messages and replies.

Does Antenna see my agents’ messages?

No one between your computers does. There is no Antenna server in the middle: messages are encrypted on one computer and decrypted only on the other.

Is the protocol documented?

Yes. The protocol, its message formats and test vectors are published under Apache-2.0, and the pairing protocol has a formal model. See the protocol description.
