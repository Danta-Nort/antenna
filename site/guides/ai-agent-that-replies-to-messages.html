In Antenna you can choose a contact and an agent (Claude Code, Codex or your own command), and from then on every message from that contact starts the agent, which reads it and replies. Antenna runs it in a sandbox, with no more permission than that contact’s trust level, and the reply appears for the other person as it is being written. It runs on your own Claude or ChatGPT sign-in, and a reply that looks like it contains a secret waits for your approval.

Typical uses

  • Your own assistant on a server. You write to your server from your laptop, and Claude Code there answers, builds and runs the tests in your project.
  • A front desk for a contact. A colleague’s questions about your project get an answer straight away, from an agent that sees only the folder of that conversation.
  • A script that reports back. Any program’s output can be sent as a live stream: my-program | antenna send --stream <contact>.

Set it up in the window

  1. On the computer where the agent should run, open Agents → Set up for a contact… (or, in a conversation, the contact card’s Agent replies → Set up…).
  2. Choose the contact and the program: Claude Code, Codex or your own command.
  3. Optionally paste a long-lived sign-in token (from claude setup-token) into Value (optional). It goes to your node once and is kept in its encrypted database. On a Mac this is the reliable way, because the sandbox cannot open the keychain.
  4. Confirm with your owner password. The rule, its last run and the Run log appear in Agents.

From a terminal it is one line: antenna wake set <contact> --cmd "claude -p --output-format stream-json". antenna wake list shows the rules and the recent runs; antenna wake off <contact> turns it off.

What the agent can and cannot do

  • Its prompt is fixed: “you have a new message, read it and reply”. The message itself never becomes the prompt; the agent reads it as data, with no more permission than the contact’s trust level.
  • It runs in a sandbox (bubblewrap or Landlock on Linux, Seatbelt on macOS): it sees its own temporary folder and that conversation’s folder, and reaches only its model provider. Your projects, your other files and the node’s keys are out of reach. Without a sandbox, Antenna does not start it.
  • Every run starts clean unless you make the agent resident (below), so an earlier message cannot leave instructions for a later run.
  • Limits: a time limit per run and a number of runs per hour, so a chatty contact cannot run up your usage.

Let it work in a project of yours

For your own computers only (∞), the agent may also work in one project folder with your toolchain: --project ~/code/payments, plus read-only --tool-path folders and the package registries it may reach with --allow-host. Antenna refuses this for any other contact, and never opens your home folder, its own data or folders that hold secrets such as ~/.ssh.

Questions

Does the other person see the reply as it is typed?

Yes, for contacts at level 3 and above: a live bubble that grows as the agent writes and becomes an ordinary message at the end. Levels 1 and 2 get the finished reply.

What if the agent writes a password or a key into its reply?

The stream stops for the other person and the message waits for your approval. Only to your own computers does it go on.

Does it remember earlier conversations?

By default, no: each message starts a fresh run. For work that lasts hours, add --resident: the same Claude Code session then stays with the conversation, keeps what was said and decided, and each new message becomes its next turn. The messages still reach it as data from another party.
