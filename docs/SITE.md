# SITE — the antenna.contact website

The product site: description, closed-beta form, handler for invite links `https://antenna.contact/#…`.
Launched on 2026-10-02. Sources are in `site/`; this file describes how the site is built,
its style, files and data.

## Summary

| What | Where |
| --- | --- |
| Site | https://antenna.contact — Cloudflare Worker `antenna-site` + static files (`site/public/`) |
| Beta requests | D1 `antenna-beta`, table `beta_requests` (only what the person entered, + time and consent version; we do not store IPs) |
| Redirects | antennachat.com, antennachat.org → `https://antenna.contact` (301, path preserved); antennachat.app → `https://antenna.contact/#beta`; www.* → apex |

## Architecture

```
site/
  wrangler.jsonc          worker antenna-site: assets, D1, rate limit, 8 custom domains, no workers.dev and no logs
  src/worker.js           domain redirects and http→https, security headers on every response, POST /api/beta
  public/                 pages, icons, assets/ — full list in "Files in public/"
  migrations/0001_beta.sql  D1 schema
  build/check.mjs         static checks before deploy (no external resources, no inline code, no broken links)
  build/browser-check.mjs check of the live site in headless Chrome (network of the invite page, form)
  build/screens.py        app window screenshot for the hero: PNG 16:10 → three WebP (2160/1440/720) — see "App window screenshot for the site"
```

- **The worker sees every request** (`run_worker_first: true`): this way the page, files, redirects and errors all get the
  same headers, and the redirect domains live in code rather than in zone settings.
- **Headers:** CSP `default-src 'none'` + only `'self'` for script/style/img/font/connect, `form-action 'self'`,
  `frame-ancestors 'none'`, `base-uri 'none'`, **Trusted Types** (`require-trusted-types-for 'script'; trusted-types 'none'` —
  the script does not use string HTML sinks at all); HSTS `max-age=63072000; includeSubDomains; preload`;
  `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, Permissions-Policy (everything off), COOP/COEP/CORP.
- **Not a single external resource:** IBM Plex fonts (Latin-subset WOFF2 from the app's fonts, OFL alongside), the mark is SVG,
  the feature icons are inline SVG in the markup, the laptop around the screenshot is drawn in CSS.
  No analytics, trackers, cookies or captcha. Workers Logs are off (`observability.enabled: false`) — the privacy
  policy promises that we do not store IPs or request data.
- **Style** — light minimalism following the v2 reference (docs/DESIGN.md "Reference v2", `docs/design/reference-light-v2.webp`),
  details in "Style" below. Language — English only (maintainer decision).

### Style (since 2026-10-02, reference v2)
- **Palette** (text contrast checked, WCAG AA and above): brand `#1560F6` — buttons (white text 5.20:1), links, icons;
  hover `#0F55E0` (6.18:1); soft background `#E8F0FE` (circles under icons); background `#FFFFFF`, hero and alternating sections
  `#F5F8FD` (brand on it 4.89:1); lines `#E3E9F2`; headings `#0B1B3A` (17:1), text `#33415C` (10.2:1), muted
  `#5F6B82` (5.37:1 / 5.04:1 on `#F5F8FD`); form field borders `#7D8BA3` (3.45:1 — WCAG 1.4.11); trust levels 1–5 —
  from gray to dark blue, every pair ≥ 4.7:1. All tokens are at the top of `assets/site.css`. There is no dark version (the reference is light).
- **Fonts:** IBM Plex Sans 400/500/600 + Plex Mono 400 (Latin, WOFF2, OFL). Medium was made on 2026-10-02 from
  `apps/antenna_desktop/assets/fonts/IBMPlexSans-Medium.ttf` with the same character set and features as the others:
  `pyftsubset … --unicodes=<as in Regular> --layout-features='kern,liga,zero' --flavor=woff2`. Light is no longer used — removed.
- **Logo:** the blue mark `assets/mark-blue.svg` + the word ANTENNA (Plex Sans Medium, letter spacing .24em); the white mark
  `assets/mark-white.svg` — for blue panels. favicon, apple-touch-icon and the OG image are generated by `docs/design/logo/build.py`
  (do not edit them by hand; to change them — edit build.py and rerun it).
- **Page:** header (mark, anchors Product · How it works · Security · Status, button Join the beta — there are no accounts, no "Sign in")
  → hero (heading "Private messaging for people and agents.", the app window on a CSS laptop) → 4 features
  (`#product`) → Why → How it works (3 steps) → Security (7 cards, levels 1–5) → Who it’s for → Status (honest) →
  beta form → footer. The header is fixed: where scroll-driven animations exist (Chrome, Safari 26), it is transparent at the top
  and turns white with a thin line on scroll, without JS; in other browsers it is always pale blue.
- **Accessibility:** 2 px focus ring in brand blue on all links and buttons; skip link; heading order h1 → h2 → h3;
  `prefers-reduced-motion` turns off smooth scrolling and transitions; no horizontal scrolling from 360 px.

### App window screenshot for the site
The hero shows the real app window in the light theme: PNG 2160×1350 (16:10). To rebuild:
```bash
cp <new screenshot>.png site/public/assets/screen-light.png     # or: python3 site/build/screens.py <path to png>
python3 site/build/screens.py      # → screen-light.webp (2160), -1440.webp, -720.webp; quality 85, budget 250 KB per file
```
The script checks 16:10 (to match `width/height` in `<img>`), lowers the quality down to 70 if the budget is exceeded and prints the result; it needs
Pillow with WebP. `srcset`/`sizes` are in `index.html` (1x desktop takes 720, 2x — 1440,
large 2x screens — 2160). The file names stay the same → returning visitors see the new screenshot within an hour (`assets/` cache).
If the meaning of the screenshot changes — update `alt` in `index.html`.

### Local preview (no deploy)
```bash
cd site && npx --yes wrangler@4 dev --ip 127.0.0.1 --port 8799 --local-protocol https \
  --compatibility-date 2026-08-27 --persist-to <scratch>/wrangler-state
```
This is the same worker — the same headers (CSP), `.assetsignore` and 404. `--compatibility-date` is for dev only (gotcha S.7),
`--persist-to` keeps the local D1 out of the tree. The form can be tried locally after
`npx --yes wrangler@4 d1 execute antenna-beta --local --persist-to <the same directory> --file=migrations/0001_beta.sql`.
Screenshots — puppeteer-core and Chrome (as in `browser-check.mjs`, paths from `PUPPETEER_CORE` and `CHROME`) with `acceptInsecureCerts: true`.

### Invite link handler
An invite of the form `https://antenna.contact/#<E_A>.<s>.<relay>[.<direct>]` (format `antenna_proto::invite`, PROTOCOL §3;
`#x://pair#…` and `#antenna://pair#…` are accepted too). The browser does not send the part after `#` to the server. `site.js`:
reads the fragment locally, checks the format (52 base32 characters ×2, base64url), shows "Open in Antenna"
(`antenna://pair#…` — the app will learn to open the scheme later) and "Copy link" with the same text (it is already understood by
`antenna join` and the "Join" field), then `history.replaceState` removes the fragment from the address bar and the tab history.
A broken link → "This invite link looks damaged". Ordinary anchors (`#beta`) are left alone.
Checked in headless Chrome: 10 page requests — all same-origin (document, css, js, 4 fonts, the svg mark, the webp screenshot,
favicon), the invite is neither in the request line nor in the headers; no CSP violations (light version — 2026-10-02, live site,
worker version `d7d7ab5c`, Chrome 131).

### Closed-beta form
`POST /api/beta` (JSON): email (required), agents (Claude Code, Codex, Cursor, other MCP, own, none yet) + "other",
scenario, consent (required). Spam protection without third-party services:
1. **proof-of-work** in the browser: SHA-256(`antenna-beta/v1|ts|email|n`) with 15 zero bits (~33 thousand hashes, ~1–2 s),
   the worker verifies it with one hash, window ±30 min (the difficulty is in `site.js` and `worker.js`, `check.mjs` makes sure they match);
2. Workers **rate limit** (`BETA_RL`: 5 requests/60 s per address, in edge memory only; approximate — see the gotchas);
3. honeypot field `website`; `Origin` check; 8 KB body limit;
4. a global fuse: more than 60 new requests within 10 minutes → 503.
A repeated request with the same email updates the record (`submissions + 1`), the response is the same — the form does not reveal who is already on the list.

## Changing the site

- If you change the terms in `privacy.html`, change the date there and `CONSENT_VERSION` in `worker.js`.
- `assets/*` files are cached in the browser for an hour (fonts — for a year, the file name is the version). An urgent CSS/JS fix
  is seen by returning visitors within an hour. **An incompatible CSS change** (new markup does not work with the old style) —
  bump `?v=N` on `site.css` in all three pages (currently `?v=2`, light version): the address is new, so the browser fetches it immediately.

## Gotchas (site)

| # | Symptom | Cause | Fix |
| --- | --- | --- | --- |
| S.1 | In headless Chrome "a request carries the invite" | puppeteer `request.url()` appends the fragment to the document address (in CDP it is in a separate field `urlFragment`), it does not go over the network | Check the address before `#` and the headers (`browser-check.mjs`) |
| S.2 | Hidden `hidden` blocks are visible | `display: grid/flex` from classes overrides the browser's `[hidden]` | `[hidden] { display: none !important; }` |
| S.3 | The rate limit let through 10 requests out of 25 in a row | Workers Rate Limiting is approximate, counted per location/isolate | It is a fuse, not an exact counter; the main protection is proof-of-work + the global D1 fuse |
| S.4 | `check.mjs` failed on its own comment | The search for HTML sinks catches the word in a comment | Do not mention sink names in `site.js` comments |
| S.6 | `/privacy.html` answers 307 | `html_handling: auto-trailing-slash` redirects to the canonical `/privacy` | As intended; links go to `/privacy` |
| S.7 | `wrangler dev`: "This Worker requires compatibility date 2026-09-01, but the newest date supported by this server binary is 2026-08-27" | The local workerd in wrangler 4.145 is older than the date in `wrangler.jsonc`; does not affect deploy (Cloudflare checks the date) | For dev — the flag `--compatibility-date 2026-08-27`; do not touch `wrangler.jsonc` |
| S.8 | The PNG screenshot source would have gone to the site as an extra file | Wrangler uploads the whole `public/` | `public/.assetsignore` (gitignore syntax; the file itself is not uploaded either) — checked: `/assets/screen-light.png` and `/.assetsignore` → 404 |
| S.9 | `.tag`/`.eyebrow` labels in cards and on privacy came out gray instead of blue | `.card p` and `.doc p` are more specific than a single class | The label color is also set for `.card .tag`, `.card .eyebrow`, `.doc .eyebrow` |
| S.10 | Right after `wrangler deploy` new files (`/favicon-32.png`, `/apple-touch-icon.png`, `/assets/screen-light-720.webp`) — 404, body 848 B | Rollout: for a few seconds part of the requests is served by the previous version (848 B is the size of the **old** 404 page) | After ~half a minute — 200. Tell by the 404 body size: old or new page. Browsers do not cache such a 404 (the worker sets `no-store` on non-200) |
